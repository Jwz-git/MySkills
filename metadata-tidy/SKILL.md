# Metadata Tidy 技能

系统性地在多文件范围内重组 Obsidian 笔记的 frontmatter。本技能处理标签、别名、标题、cssclasses、日期及其他 YAML 属性，并能检测元数据问题，如重复内容、错误标题和孤立别名。

## 核心原则

- **先读后改。** 修改前先读取所有受影响文件的 frontmatter，使用并行读取。
- **先规划后执行。** 当用户意图清晰时，编辑前先简要说明变更计划。若用户提供明确的映射表，跳过确认直接执行。
- **并行编辑。** 所有文件的编辑相互独立，应一次性成批提交。
- **编辑后校验。** 使用 `grep` 确认旧值已清除，新值已生效。
- **只改 frontmatter。** 除非用户明确要求同时修正文内标题/正文，否则不修改正文内容。
- **不产出额外文件。** 在对话中给出摘要，除非用户要求，不创建报告文件。

## 工作流程

### 步骤 1：理解目标状态

用户可能通过以下方式表达意图：

- **口头描述**："把 paper, VLM, LoRA 这类标签改成 paper/lora, paper/vlm 的层级结构"
- **内联映射表**：用 Markdown 表格给出旧值 → 新值
- **引用既有方案**："按这个方案整理"，指向库内的某个方案文档或笔记

在开始前先澄清歧义：
- 范围包含哪些文件/目录？
- 标签是扁平结构还是层级结构（使用 `/` 的嵌套标签）？
- 是否有需要排除的文件？

### 步骤 2：发现并读取

1. 使用 `Glob` 查找范围内的所有文件（如 `论文/**/*.md`、`数据结构/*.md`）。
2. 并行读取所有文件的 frontmatter，通常前 10-15 行就足够。
3. 记录无 frontmatter 的文件并跳过。

### 步骤 3：规划变更

为每个文件构建旧 frontmatter 值 → 新 frontmatter 值的映射。

**当用户提供明确映射表时**：直接应用。

**当用户用口头描述意图时**：先拟定映射并在编辑前给出简要摘要。摘要应包含：
- 受影响文件数量
- 旧 → 新标签映射
- 发现的任何问题（重复内容、错误标题、孤立别名）

### 步骤 4：执行

使用 `Edit`（`replace_all: false`）并行成批编辑所有文件，精确匹配 frontmatter 中的旧字符串。

对于 YAML 列表格式的标签：
```yaml
tags:
  - paper
  - VLM
  - localization
```
替换为：
```yaml
tags:
  - paper/localization
  - paper/vlm
```

对于内联格式标签（`tags: [paper, VLM]`），需严格匹配内联格式。

### 步骤 5：校验

进行两次 grep 校验：

1. **旧值已消失**：在 frontmatter 语境中搜索旧标签/别名值（如列表格式使用 `^\s+-\s+old-tag-name\s*$`）
2. **新值已出现**：搜索新的层级标签或属性值

对每个检查报告通过/失败。若仍有旧值，继续修复。

### 步骤 6：汇总报告

输出汇总表：

```
| 目录 | 文件数 | 旧标签数 | 新标签数 |
|------|--------|---------|---------|
| 论文/分析/ | 5 | 30 → 13 | ... |
| 论文/AI分析/ | 11 | 46 → 22 | ... |
```

包含统计信息：旧的唯一标签数量 → 新的唯一标签数量，以及减少百分比。

## 常见模式

### 标签层级重构

这是最常见的操作。旧的扁平标签如 `paper`、`VLM`、`localization`、`point-cloud` 会变为层级标签：`paper/localization`、`paper/localization/point-cloud`、`paper/vlm`。

在 Obsidian 中，层级标签（如 `paper/localization`）可作为可点击的筛选项。标记为 `paper/localization/point-cloud` 的文件会同时出现在标签面板的 `paper/localization` 与 `paper/localization/point-cloud` 下。

### 识别元数据问题

读取 frontmatter 时留意：
- **重复内容**：两个文件标题/别名相同但文件名不同
- **错误标题**：标题与文件名或实际内容不一致
- **复制粘贴标签**：明显属于其他论文的标签（如 Scene Graph 论文中出现 LoRA/NAS 标签）
- **孤立别名**：别名指向不存在的笔记

将这些问题提示给用户。除非用户明确要求，否则不要重命名文件——重命名可能破坏维基链接。

### 中文标签处理

中文标签（如 `数据结构`、`考试复习`）在 Obsidian 中可用，但维护成本更高。若在转为结构化体系时，可建议层级化等价标签（如 `study/data-structure`、`study/review`）。

## 示例

**User**: 帮我把所有论文笔记的标签整理一下，paper 这个标签没用了去掉，剩下的改成 paper/xxx 的层级结构

**技能流程**：
1. Glob `论文/**/*.md` 查找所有文件
2. 并行读取所有文件的 frontmatter
3. 构建映射：提取所有唯一标签并提出层级方案
4. 向用户呈现摘要并确认
5. 并行成批编辑文件
6. 使用 grep 校验旧标签已消失、新标签已出现
7. 报告："更新 18 个文件，42 个标签 → 13 个标签（减少 69%）"
