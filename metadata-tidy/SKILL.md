# Metadata Tidy 技能

系统性地在多文件范围内整理 Obsidian/Markdown 笔记的 frontmatter。适用于课程笔记、读书笔记、项目文档、日记等通用场景。

> 论文笔记的元数据标准化（`paper/xxx` 标签、原文链接、五段式结构）由 `paper-research` 技能处理。本技能处理通用场景。

## 核心原则

- **先读后改。** 修改前先读取受影响文件的 frontmatter，建立全局视图后再动手。
- **少问但问准。** 范围、目标状态或破坏性操作不清楚时先问；用户给出明确映射或目录时直接执行。
- **保留现有风格。** 默认保留每个文件已有的 YAML 写法、字段顺序和缩进；只有用户要求统一格式时才整体重排。
- **结构优先。** 能用 frontmatter/YAML 解析或局部结构化处理时，不要依赖容易误伤正文的全局字符串替换。
- **批量提交。** 多文件编辑尽量合并为少量 patch，避免逐文件来回确认。
- **编辑后校验。** 在 frontmatter 语境中确认旧值已清除、新值已生效；搜索工具优先用 `rg`，不可用时用 `grep`/`find`。
- **只改 frontmatter。** 除非用户明确要求同时修正文内标题、正文标签或文件名，否则不修改正文内容。
- **不产出额外文件。** 在对话中给出摘要；除非用户要求，不创建报告文件。

## 工作流程

### 步骤 1：理解目标状态

用户可能通过以下方式表达意图：

- **口头描述**：「把课程标签改成 course/xxx 层级结构」「给所有日记加上 cssclasses: daily」
- **内联映射表**：用 Markdown 表格给出旧值 → 新值
- **引用既有方案**：「按这个方案整理」，指向库内的某个方案文档

只在影响执行安全的地方澄清歧义：
- 范围包含哪些文件/目录？
- 标签是扁平结构还是层级结构（使用 `/` 的嵌套标签）？
- 是否有需要排除的文件？
- 操作类型是什么（重命名/合并/删除/添加/重构层级）？
- 是否允许标准化 YAML 格式，还是必须保持每个文件原样风格？

### 步骤 2：发现并读取

1. 查找范围内的所有 `.md` 文件：优先 `rg --files -g '*.md'`，若环境没有 `rg`，用 `find` 或当前工具的 Glob 能力。
2. 并行读取所有文件的 frontmatter。读取到第二个 `---` 结束标记为止，避免按固定行数截断。
3. 记录无 frontmatter 的文件并跳过。
4. 汇总所有唯一标签/别名/属性值，形成全局视图。

### 步骤 3：规划变更

为每个文件构建旧 frontmatter 值 → 新 frontmatter 值的映射，并注明是否会新增、删除、重命名或合并字段。

**当用户提供明确映射表时**：直接应用。

**当用户用口头描述意图时**：先拟定映射并在编辑前给出简要摘要。摘要应包含：
- 受影响文件数量
- 旧 → 新值映射
- 发现的任何问题（重复内容、错误标题、孤立别名）
- 格式策略（保留现状/统一为列表格式/统一为内联格式）

### 步骤 4：执行

批量编辑所有文件，只改 frontmatter 区块。小范围重命名可精确匹配 frontmatter 中的旧行；涉及字段重排、去重、日期补全或多格式混用时，优先用结构化方式生成新的 frontmatter 区块，再用 patch 替换整个区块。

#### YAML 格式注意事项

**列表格式**（常见于 `tags`、`aliases`、`cssclasses`）：

```yaml
tags:
  - old-tag-a
  - old-tag-b
```

替换时精确匹配整行（含前导空格和 `- `），避免误伤正文或其他字段。

**内联格式**：

```yaml
tags: [old-tag-a, old-tag-b]
```

需严格匹配内联格式，注意逗号后的空格。若要在内联数组中增删多个值，先确认不会破坏引号或逗号。

**两种格式混用时**：根据文件现有风格保持一致，不做格式转换（除非用户要求统一）。

**引号处理**：含特殊字符（`: # [ ] { } , & * ? | - < > = ! % @ \`）的值需用引号包裹。

**去重处理**：合并标签或 aliases 后，同一列表中只保留一个值，并尽量保持原有排序；用户要求按字母或主题排序时再重排。

### 步骤 5：校验

进行两次搜索校验：

1. **旧值已消失**：在 frontmatter 语境中搜索旧值（如列表格式使用 `^\s+-\s+old-value\s*$`）
2. **新值已出现**：搜索新值

对每个检查报告通过/失败。若仍有旧值，先判断是否位于正文；若旧值仍在 frontmatter 中，继续修复。

### 步骤 6：汇总报告

输出汇总表：

```
| 目录 | 文件数 | 变更类型 | 旧值数 | 新值数 |
|------|--------|---------|-------|-------|
| 课程/ | 12 | 标签重构 | 28 | 10 |
| 读书笔记/ | 8 | 添加 cssclasses | - | 8 |
```

包含统计信息：唯一值数量变化，以及减少/增加百分比。若只改少量文件，可用简短列表代替表格。

## 常见操作模式

### A. 标签层级重构

将扁平标签重组为层级结构。

在 Obsidian 中，层级标签（如 `course/math`）可作为可点击的筛选项。标记为 `course/math/calculus` 的文件会同时出现在 `course/math` 与 `course/math/calculus` 下。

**示例**：

| 旧标签 | 新标签 |
|-------|-------|
| `数学` `线性代数` | `course/math/linear-algebra` |
| `数学` `微积分` | `course/math/calculus` |
| `编程` `Python` | `dev/python` |

### B. 标签合并/重命名

将多个含义相近的标签统一为一个。

**示例**：`todo`、`TODO`、`待办` → `status/todo`

合并前先列出所有变体及其使用频次，确认用户意图。

### C. 标签清理/删除

移除无用标签（如自动导入产生的噪音标签、不再使用的分类）。

**示例**：删除所有文件中的 `imported`、`unread` 标签。

### D. 批量添加属性

为符合条件的文件统一添加属性值。

**示例**：
- 给 `日记/` 目录下所有文件添加 `cssclasses: [daily-note]`
- 给无 `date` 字段的文件根据文件名补充日期

### E. 属性值规范化

统一属性值的格式或大小写。

**示例**：
- `Date: 2024/3/5` → `date: 2024-03-05`（ISO 格式）
- `Title` → `title`（属性名小写统一）

### F. 清理冗余/过时属性

检测并移除不再需要的 frontmatter 字段。

**示例**：移除所有文件中的 `original_pdf`、`category`、`modified` 等废弃字段。

## 识别元数据问题

读取 frontmatter 时留意以下问题并提示用户：

| 问题类型 | 说明 | 建议操作 |
|---------|------|---------|
| **重复标题/别名** | 两个文件 `title`/`aliases` 相同但文件名不同 | 提示用户确认是否重复 |
| **错误标题** | `title` 与文件名或实际内容不一致 | 建议修正 |
| **孤立别名** | `aliases` 指向不存在的笔记 | 建议清理 |
| **标签拼写变体** | `python`/`Python`/`PYTHON` 共存 | 建议统一 |
| **空 frontmatter** | 只有 `---\n---` 无实际内容 | 提示用户是否补充或删除 |
| **无效 YAML** | frontmatter 语法错误（缺少引号、缩进错误） | 修复语法 |

除非用户明确要求，否则**不要重命名文件**——重命名可能破坏维基链接。

## 中文标签处理

中文标签（如 `数据结构`、`考试复习`）在 Obsidian 中可用，但可能导致以下问题：
- 搜索时需切换输入法
- URL 编码后可读性差
- 与英文标签混用时体系不统一

建议方案：用 `topic/english-slug` 层级标签替代，如 `study/data-structure`、`study/review`。但这取决于用户偏好——若用户习惯中文标签，尊重其选择。

## 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 文件无 frontmatter | 跳过并记录；若用户要求，可添加 frontmatter 模板 |
| frontmatter 语法错误 | 尝试修复常见问题（缺少闭合 `---`、缩进错误）；无法自动修复时报告给用户 |
| 超大规模（500+ 文件） | 分批处理，每批 50-100 个文件，批间报告进度 |
| 标签/别名中含特殊字符 | 使用 YAML 引号包裹：`"C++"`、`"node.js"` |
| 同一标签在列表格式和内联格式中混用 | 按各文件现有格式处理，不做格式转换 |
| 用户要求的操作可能破坏链接 | 警告用户并请求确认后再执行 |
| 文件使用 `#tag` 正文标签而非 frontmatter | 说明本技能仅处理 frontmatter 标签；若用户需要迁移正文标签到 frontmatter，需额外确认 |

## 示例

**User**: 帮我把课程笔记的标签整理一下，现在都是扁平的，改成层级结构

**技能流程**：
1. 查找 `课程/` 下所有 Markdown 文件（优先 `rg --files`，不可用时用 `find`/Glob）
2. 并行读取所有文件的 frontmatter
3. 构建映射：提取所有唯一标签，按主题分组，提出层级方案
4. 向用户呈现摘要并确认
5. 批量编辑 frontmatter
6. 使用搜索校验旧标签已消失、新标签已出现
7. 报告：「更新 24 个文件，35 个标签 → 12 个标签（减少 66%）」
