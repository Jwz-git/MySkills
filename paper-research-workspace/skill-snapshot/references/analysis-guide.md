# 论文分析报告输出格式指南

## 读者假设：面向初学者

默认读者对该论文方向没有系统背景，不应把熟悉某个领域、常见缩写或默认实验设置当作前提。详细讲解的目的，是让读者能够沿着“要解决什么问题 → 为什么原有方案不够 → 新方法如何工作 → 实验为何能支持结论”的路径独立理解论文，而不是增加无信息量的篇幅。

- 术语、缩写、数据集、评价指标和关键模块第一次出现时，先用一句通俗的话说明“它是什么、为什么此处需要它”，再给出准确的论文表述。
- 每个复杂内容遵循“直觉/类比 → 整体位置 → 技术细节 → 与本文结论的关系”的顺序。只有在它确实能降低理解门槛时才使用类比，避免不准确的类比取代定义。
- 不跳过中间因果：说明一个组件接收什么、输出什么、解决了前一步的什么困难，以及它怎样影响后续模块或结果。
- 详细不等于臆测。没有出现在原文中的实现细节、数值或因果关系要明确说明依据不足，不能为了“讲透”而补造。

# 1. 五段式结构写作指南

## 1.1 一句话总结

用 1-2 句话概括论文核心贡献。**必须包含**：核心问题 + 提出方法 + 关键结果。

**格式要求：**
- 关键术语和核心数字用 `==高亮==`（如 `==SOTA==`、`==28.4 BLEU==`、`==3 倍==`）
- 多个贡献时选最重要的 1-2 个

**示例：**
> 本文提出了 Transformer 架构，完全基于注意力机制摒弃了 RNN 和 CNN，在 ==WMT 2014 英德翻译== 任务上取得了 ==28.4 BLEU== 的 SOTA 结果，训练速度比主流模型提升 ==3 倍以上== 。

## 1.2 论文基本信息

```markdown
| 属性 | 内容 |
|------|------|
| **论文标题** | ... |
| **作者** | ... |
| **机构** | ... |
| **arXiv ID** | ... |
| **发表日期** | ... |
| **论文类型** | 实验类/理论类/综述类/系统类 |
| **核心方法** | ... |
| **基线模型** | ... |
| **开源代码** | ... |
| **评估数据集** | ... |

> [!info] 论文定位
> 本文属于 ==领域A== 与 ==领域B== 的交叉领域，聚焦于解决...问题。
```

信息不完整时标注 `[待补充]`，不要臆造。

## 1.3 核心内容详解（四小节）

根据论文类型调整各小节标题：

| 论文类型 | ①背景小节 | ②方法小节 | ③实验小节 | ④展望小节 |
|----------|-----------|-----------|-----------|-----------|
| **实验类** | 研究背景与问题 | 方法方案 | 实验/结果 | 改进空间与展望 |
| **综述类** | 研究领域概览 | 分类与对比 | 关键发现与趋势 | 开放问题与展望 |
| **理论类** | 理论动机 | 理论框架 | 理论结果 | 局限与拓展 |
| **系统类** | 需求与挑战 | 系统架构 | 性能基准 | 改进方向 |

### ① 研究背景与问题

**目标：** 让读者理解为什么这个问题重要、为什么现有方法不够。

**必须涵盖：**
- 领域背景与基础概念定义（对不熟悉者解释术语、缩写和问题设定）
- 现有主流方法及基本思路
- 现有方法的具体局限（作者指出的技术挑战）
- 问题的重要性（学术/应用价值）
- 本文动机（作者为什么认为他们的方案能解决问题）

> 假设读者是初学者。先说明任务的输入、希望得到的输出和现实用途；再解释关键概念（通俗定义/必要时的直观类比/准确术语），最后说明它们如何导致本文的问题。不要把“现有方法的局限”写成只有行内人才懂的一句术语。

### ② 方法方案

**目标：** 讲清楚方法如何工作、每一步为什么这样设计。

**必须涵盖：**
- **核心思想**：一句话概括方法基本思路
- **整体架构**：输入→处理→输出流程
- **关键技术细节**（每个组件）：输入输出、内部机制、设计动机、与现有方法的区别
- **训练/推理流程**（实验类）：损失函数、训练策略、推理过程
- **与现有方法的关键区别**

> - **逐层深入**：先整体框架，再逐层展开细节。对每个关键组件明确说明输入是什么、输出是什么、它做了什么、为什么这样设计，以及相对于已有方法解决了什么问题。
> - **对比说明**：用对比方式呈现创新点
> - **公式处理**：先解释公式要解决的计算问题，再说明每个符号、运算顺序、公式的直观含义和与系统组件的对应关系；必要时用一个不引入论文外结论的小型符号示例串起计算过程。
> - **可视化描述**：即使论文没有图，也要用文字描述方法结构
> - **背景概念解释**：注意力机制、残差连接等子技术不能只报名称；用初学者能跟上的语言说明它们的作用，再说明本文如何使用它们。

### ③ 实验效果

**目标：** 回答实验证明了什么、结果有多好、为什么好。

**必须涵盖：**
- **实验设置**：数据集（规模/来源/特点）、评价指标（指标数值的好坏方向和选择原因）、Baseline（为什么是合理对照）、环境
- **主要结果**：主实验结果 + 具体数据 + 核心发现
- **消融实验**：验证的设计选择、各组件贡献度、关键参数影响
- **可视化分析**：注意力图、特征可视化等及其揭示的信息
- **结果解读**：为什么在这些数据集/指标上表现好/不好？对领域的启示？

> 数据要全面，`==高亮==` 重要数值。先让初学者知道表格列、指标、基线分别代表什么，再解释数字变化的大小、方向和实际含义；不要仅罗列数字。如有错误分析、鲁棒性测试等，重点讨论。

### ④ 改进空间与展望

**目标：** 客观评价局限与合理改进方向。

**必须涵盖：**
- **局限性**（有依据）：理论局限（如假设过强）、实验局限（如数据集单一）、应用局限（如计算成本高）
- **改进方向**（具体可行）：直接扩展（其他领域/任务）、方法改进（解决具体缺陷）、理论深化
- **开放问题**：论文遗留的未解决问题

> 保持客观中立。在表述上清晰区分事实（如使用“作者指出”）与合理推论（如使用“可能暗示”）。

## 1.4 关键原图与图解

从论文 PDF 中提取重要图片，并在 `images/论文名/` 中按图意重命名后，直接嵌入分析笔记。图片目录与 `AI分析/` 同级；引用时根据笔记实际位置生成相对路径，通常为 `../images/论文名/文件名.png`。

**筛选原则：**

- 优先保留方法总览、架构、训练/推理流程、关键模块、主结果、消融、错误分析和定性案例。
- 其他图片只要能让读者更容易理解论文，也应保留并展示；例如注意力热图、失败案例、性能曲线或任务示例。
- 不保留装饰性图片、Logo、重复子图、无信息量截图或不可读图片。
- 图为矢量对象时，渲染图所在区域为 PNG；不要因为无法直接导出位图而忽略关键流程图。
- 不使用 Mermaid，也不依据文字自行重绘原论文中已有或缺失的流程图。

**文件命名：** 以图号和简短英文语义命名，例如 `fig-02-training-inference-flow.png`、`fig-04-ablation-study.png`。名称应和图注一致，避免无意义的自动编号。

**嵌入模板：**

```markdown
### 方法总览

![图 2：方法总体架构](../images/论文名/fig-02-method-overview.png)

*图 2（原论文第 3 页）：方法总体架构。*

1. **先看什么**：图中输入、图例、颜色或符号分别代表什么……
2. **输入与编码**：图左侧展示……，它把……转换为……
3. **关键模块**：中间的……负责……，这样设计是为了……
4. **输出与训练信号**：右侧表示……，它如何支撑本文的核心结论……
```

每张展示图都要提供：原始图号/页码（可获得时）、准确图注、面向初学者的读图顺序，以及它与正文论点的关系。流程图应解释输入、箭头/颜色/符号、关键模块和输出；结果图应解释横纵轴、图例、好坏方向、主要趋势和可得结论。没有能可靠提取或有助理解的图片时，简短说明原因并用文字分析，不补画图。

## 1.5 总结

```markdown
> [!abstract] 论文总结
>
> 核心贡献总结... 
>
> 实验/理论结果关键数据... 
>
> 对该领域的意义或实际应用价值...
```

简洁有力，突出最重要的贡献和数据。

# 2. 格式元素规范

| 元素 | 格式 | 用途 |
|------|------|------|
| **高亮** | `==text==` | 关键词、核心术语、重要数字（SOTA 数值、百分比提升等） |
| **加粗** | `**text**` | 强调但不至高亮级别 |
| **信息 callout** | `> [!info]` | 论文定位、背景知识 |
| **警告 callout** | `> [!warning]` | 局限性、研究空白、待改进 |
| **成功 callout** | `> [!success]` | 关键发现、核心结果 |
| **笔记 callout** | `> [!note]` | 补充信息、方法对比、模型列表 |
| **提示 callout** | `> [!tip]` | 方法优势、实用技巧 |
| **重要 callout** | `> [!important]` | 关键公式、核心机制 |
| **摘要 callout** | `> [!abstract]` | 最终总结 |
| **原论文图片** | `![图注](相对路径)` | 展示已提取的架构、流程、结果或案例图，并紧随图解 |

# 3. 增强讲解策略（完整版）

使讲解更加详尽、同时对初学者友好的六项策略：

## 策略一：层级化解释

对每个技术概念，采用三层递进式解释：

1. **一句话定义** — 最简洁的语言说明"是什么"
2. **直观类比** — 日常生活或熟悉领域的类比帮助理解
3. **技术细节** — 准确的技术描述（公式、架构图、算法步骤）

**示例（自注意力机制）：**
> **自注意力机制**是一种让序列中每个位置都能关注所有其他位置的计算机制。可以想象成模型在阅读句子中的每个词时，会同时查看句中所有其他词来理解上下文，而不是像 RNN 那样逐个词阅读。具体来说，自注意力计算 query-key 点积得到注意力权重...

## 策略二：多视角分析

对关键贡献从多个角度阐述：
- **理论视角** — 方法的理论基础和数学涵义
- **实践视角** — 工程实现中的考虑
- **对比视角** — 与现有方法有何不同、为什么更好
- **直觉视角** — 作者为什么选择此方案，直觉动机是什么

## 策略三：结构化对比

用多维对比表展示创新定位：

```markdown
| 维度 | 本文方法 | 现有方法 A | 现有方法 B |
|------|---------|-----------|-----------|
| 核心思路 | ... | ... | ... |
| 计算复杂度 | ... | ... | ... |
| 适用场景 | ... | ... | ... |
| 关键局限 | ... | ... | ... |
```

## 策略四：关键公式/算法详细解读

1. **定位** — 说明该公式/算法在方法中的位置和目的
2. **逐项解释** — 解释每个符号的含义
3. **自然语言翻译** — 用自然语言"翻译"数学表述
4. **推导直觉** — 说明公式的推导直觉（不复杂时）

## 策略五：实验结果的深层解读

不只是汇报数字：
- **为什么好/不好？** — 在特定数据集上表现好/差的原因
- **误差分析** — 方法在哪些困难场景下失败
- **计算代价** — 训练/推理效率如何
- **鲁棒性** — 对超参数、初始化等的敏感性

## 策略六：知识缺口检查

在完成每个大节后，检查初学者是否还会卡在以下问题；若会，补上简短解释或链接到前文，而不是假定读者自行补齐：

1. 这项任务的输入、输出和成功标准是什么？
2. 新术语、缩写、数据集和指标各指什么？
3. 这个模块为何出现在这里，它承接和改变了什么信息？
4. 图、表或公式应该从哪里开始读，最后能读出什么？
5. 作者的证据究竟支持什么结论，又没有支持什么结论？

# 4. 写作原则

- **初学者优先且深入而不宽泛**：默认读者没有先验知识。每个技术点回答“是什么、为什么、怎么做、与前后步骤有什么关系”；先讲核心思想→架构→细节。首次出现的术语、缩写、指标与背景技术提供必要解释，不用空泛重复填充篇幅
- **原图优先**：涉及流程、架构、结构和关键结果时，优先嵌入并解读从 PDF 提取的原论文图片；无法可靠提取时说明原因，不要用推测补图或 Mermaid 代替
- **事实优先**：关键结论有据可查，避免凭空补全与臆造
- **客观中立**：在表述上清晰区分事实与合理推论/待核实信息，避免使用括号标签
- **语言**：跟随用户语言；专业术语保留原文并附注释；`==高亮==` 标记关键术语和数字，`**加粗**` 做一般强调
