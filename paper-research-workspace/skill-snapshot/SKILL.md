# 论文完整工作流 Skill

## 1. 技能概览

### 1.1 能力矩阵

本技能整合三大核心能力，形成从检索到归档的完整闭环：

| 能力 | 说明 |
|------|------|
| **论文检索与研究** | 需求确认→arXiv检索→初筛→下载→文本提取 |
| **深度结构化分析** | 面向初学者的五段式报告：一句话总结→基本信息→核心详解（四小节）→关键原图与图解→总结 |
| **笔记格式标准化** | Frontmatter/Tags/Links整理、文档结构标准化、批量编辑 |

### 1.2 工具链

| 工具 | 用途 |
|------|------|
| `arxiv-search` skill（如可用） | 学术论文检索、摘要获取与 PDF 下载 |
| Web/浏览器/官方页面 | 获取论文元数据、代码链接、会议页面和兜底搜索 |
| `curl` | PDF 下载兜底：`curl -L -o "path/file.pdf" "https://arxiv.org/pdf/XXXX.XXXXX"` |
| `pdfplumber` (Python) | PDF 文本提取 |
| `PyMuPDF` / `fitz`（Python） | 提取 PDF 内嵌位图；必要时将包含矢量图的图区域渲染为 PNG |
| 可用的文件读写工具 | 读取 PDF/Markdown，写入分析笔记，批量编辑归档 |
| `rg`/`grep`/`find` | 文件查找与校验；无 `rg` 时使用 `grep`/`find` |

### 1.3 工作目录

```
知识库根目录/
├── 论文/
│   ├── 论文原件/        # 存放 PDF 原文
│   ├── AI分析/          # 存放论文笔记
│   └── images/          # 与 AI分析/ 同级，存放论文相关图片
│       └── 论文名/      # 一篇论文的已筛选、重命名后的关键图片
```

用户目录结构不同时，先确认对应关系再执行。

### 1.4 工作流总览

按“需求确认与检索 → 选择论文 → 下载 PDF、提取正文和图片 → 深度分析报告 → 格式标准化 → 归档与汇总”的顺序执行。深度分析时，优先使用从原论文提取的架构图、流程图及其他有助理解的图，不另行绘制流程图。

### 1.5 核心原则

- **来源优先** — 论文事实以 arXiv、publisher、OpenReview、ACL Anthology、项目主页等主来源为准；时间敏感问题必须联网确认。
- **真实可信** — 关键结论必须符合原文，缺失信息标注 `[待补充]` 或说明依据不足，避免凭空补全。
- **宁深勿浅** — 技术点要讲清楚“是什么、为什么、怎么做、证据是什么”。
- **初学者视角** — 默认读者没有该论文方向的先验知识。先补足理解当前内容所需的概念和问题背景，再讲术语、公式、模块与结论；详细解释应服务于理解，不能用空泛重复凑篇幅。
- **原图优先** — 从 PDF 提取并保留能帮助理解的原论文图片，尤其是架构、训练/推理流程、关键结果、消融和定性案例图；在 Markdown 中直接展示和解读，不使用 Mermaid 重绘流程。
- **减少无谓等待** — 只有论文选择、知识库路径或关键过滤条件会影响结果时才停下来问；可合理默认时先说明默认值并继续。

## 2. 第一阶段：需求确认与检索规划

与用户确认以下信息后制定检索策略。若缺失信息会明显改变范围或成本，先提问；否则使用合理默认并在结果中写明。

1. **研究主题与关键词** — 核心关注什么？是否有已知的重要论文作为起点？
2. **过滤条件**：
   - 年份范围（默认使用执行当天往前约 2 年；用户要求经典论文时不限制年份）
   - 论文类型（实验类/综述类/理论类）
   - arXiv 分类（如 cs.CV 计算机视觉、cs.LG 机器学习、cs.CL 计算语言学等）
   - 会议来源偏好（如 CVPR, NeurIPS, ICML, ACL）
3. **数量目标** — 期望分析多少篇？（推荐 3-5 篇可深入分析）
4. **特殊要求** — 排除/侧重特定子方向、只关注有开源代码的论文等
5. **用途与侧重点** — 综述/落地/复现？更看重方法创新还是实验指标？

> 如果用户一次性信息足够充分，可直接进入检索，无需重复确认。用户只说“找最新/最近论文”时，必须使用当前日期计算时间范围，不要写死年份。

## 3. 第二阶段：论文检索与筛选

### 3.1 构建检索 Query

设计 1-2 组检索式，覆盖不同角度：
- 精确短语用引号包裹：`"visual place recognition"`、`"low-rank adaptation"`
- 组合概念：`"vision language model" AND "localization"`
- 排除噪音：`"LoRA" ANDNOT "survey"`
- 设置 arXiv 分类过滤，提升结果精准度

### 3.2 执行检索

优先使用 `arxiv-search` skill 进行检索：
- `max_results: 15-20` — 获取足够候选
- `sort_by: "relevance"` — 默认按相关性排序；调研最新进展时用 `"date"`
- `categories` — 设置分类过滤

> 兜底：若 `arxiv-search` 不可用，使用 Web 搜索或直接访问 arXiv、OpenReview、ACL Anthology、publisher 页面等主来源。搜索结果中若包含博客/新闻，可作为线索，但不要把它们当作论文事实来源。

### 3.3 初筛与排序

- 检查标题与用户主题的匹配度
- 获取摘要（`get_abstract`）评估内容相关性
- 评估来源（arXiv 本身、疑似顶会投稿）
- 多组检索结果合并去重

### 3.4 逐篇梗概

为每篇候选生成清晰梗概，**用于用户选择**。推荐格式：
- 100-150 字摘要 + 3-5 条要点
- 覆盖：研究问题、方法思路、核心结果/贡献、适用场景/局限（若摘要可推断）

当用户没有指定具体论文时，请用户从候选列表中选择后再深入下载/分析。若用户明确要求“你来选 Top N”或“自动处理最相关的几篇”，按相关性、时间、来源可信度和可获取性排序后继续，并说明选择依据。

## 4. 第三阶段：论文下载与文本提取

### 4.1 下载 PDF

使用 `arxiv-search` skill 下载 PDF（如可用）。
> 兜底方案：`curl -L -o "论文/论文原件/文件名.pdf" "https://arxiv.org/pdf/XXXX.XXXXX"`

PDF 文件名使用基于标题的简短命名：提取论文标题中的核心关键词，用连字符连接，简洁直观。例如：`MLP-Memory.pdf`、`VLM-Loc.pdf`、`DC-VLAQ.pdf`

### 4.2 提取正文文本

使用 Python 的 `pdfplumber` 库提取 PDF 文本内容：

```python
import pdfplumber
with pdfplumber.open(pdf_path) as pdf:
    for page in pdf.pages:
        text = page.extract_text()
```

> 直接读取 PDF 失败时，用 `pdfplumber` 兜底。先检查系统是否已有该库（`python3 -c "import pdfplumber"`）；缺失时优先在当前 Python 环境或项目虚拟环境安装，安装失败则说明原因并请求用户提供可读文本。

### 4.3 提取、筛选与整理论文图片

对每篇已下载并需要深度分析的 PDF，都要提取图片；不要只提取正文文本。

1. **创建最终目录** — 在与 `AI分析/` 同级的 `images/论文名/` 创建目录。`论文名` 使用与笔记/PDF一致、可作路径名的简短标题，例如 `images/MLP-Memory/`。
2. **尽量完整提取** — 优先用 PyMuPDF 提取页面内嵌图片；图是 PDF 矢量对象、内嵌提取不完整或清晰度不足时，将对应图所在区域以足够分辨率渲染为 PNG。不要把整页截图当作单张论文图，除非无法可靠裁出图且整页本身确有必要保留。
3. **结合图注筛选** — 阅读正文中的图号、图注和引用上下文，识别每张图片在论文中的作用。优先保留：方法总览/模型架构、训练或推理流程、关键模块细节、主实验曲线或可视化结果、消融图、错误分析和定性案例。删除或不放入最终目录的内容包括：期刊 Logo、作者头像、重复小图、纯装饰图、无法辨认或无法为分析提供信息的图片。
4. **语义化重命名** — 仅保留的重要图片必须重命名，避免 `image1.png`、`xref-12.png` 等无意义文件名。使用小写 ASCII、连字符和图号前缀，例如：
   - `fig-01-method-overview.png`
   - `fig-02-training-inference-flow.png`
   - `fig-03-main-results.png`
   - `fig-04-ablation-study.png`
   - `fig-05-qualitative-examples.png`
   名称应以论文图注和实际内容为准；同一图的多个子图可保留为同一张完整图，只有独立说明更清楚时才拆分。
5. **质量与可追溯性检查** — 打开/检查保留图片，确认文件可读、文字和箭头清晰、图号与图注对应；记录原始页码和图号，以便在笔记图注中标明。无法可靠提取的图应在报告中简短说明原因，不能自行补画。

最终 `images/论文名/` 只存放筛选后的重要图片；临时提取物在完成筛选后清理。图片路径必须与该论文的 Markdown 笔记路径相匹配。

### 4.4 获取元数据

访问 `https://arxiv.org/abs/XXXX.XXXXX` 或论文官方页面获取标题、作者、摘要、日期、代码链接等元数据。

### 4.5 保存 PDF

- 将 PDF 保存到 `论文/论文原件/` 目录
- 文件名使用基于标题的简短命名（如 `MLP-Memory.pdf`、`VLM-Loc.pdf`），提取核心关键词，简洁直观

## 5. 第四阶段：深度结构化分析报告生成（核心）

**这是本技能最核心的环节。** 对每篇论文生成五段式深度分析报告。讲解要详尽，宁深勿浅，每个关键技术点都要讲透。

### 5.1 输入获取

根据输入类型选择获取方式，优先拿到完整正文：

| 输入类型 | 获取方式 |
|----------|---------|
| PDF 文件 | 直接读取；失败则用 `pdfplumber` 兜底 |
| DOI / arXiv ID | 获取元数据并下载/读取 PDF；只有摘要可用时标注依据范围 |
| 论文链接 | 支持 arXiv、ACL Anthology、OpenReview、publisher 页面、项目主页等。遇付费限制则说明并请用户提供 PDF |
| 论文标题 | 用搜索工具查找并确认匹配；多个候选时请用户确认 |
| 论文片段（摘要/段落） | 基于现有片段分析，标注"[基于部分内容分析]"，建议用户提供完整论文 |

### 5.2 论文类型识别

先判断论文类型以决定分析侧重点。判断依据为标题、摘要和引言前几段；无法确认时按实验类保守处理并说明。

| 论文类型 | 特征 | 分析侧重点 |
|----------|------|-----------|
| **实验类** | 提出新模型/方法，有定量实验 | 方法架构、实验结果、消融实验 |
| **理论类** | 以数学证明/定理为主 | 理论框架、证明思路、理论意义 |
| **综述类** | 系统梳理某一领域 | 分类体系、发展趋势、研究空白 |
| **系统/框架类** | 提出软件系统或工程框架 | 系统架构、设计决策、性能基准 |
| **人文社科类** | 定性研究为主 | 研究方法、论证逻辑、社会意义 |

### 5.3 五段式输出结构

> 完整的格式模板、写作指南和示例见 `references/analysis-guide.md`。

按以下五段结构生成报告：

#### 5.3.1 一句话总结

1-2 句概括核心贡献，`==高亮==` 关键术语和核心数字。包含：核心问题 + 提出方法 + 关键结果。

#### 5.3.2 论文基本信息

表格呈现元数据（标题/作者/机构/arXiv ID/日期/类型/方法/基线/代码/数据集），附 `> [!info] 论文定位` callout。信息不完整时标注 `[待补充]`，不要臆造。

#### 5.3.3 核心内容详解（四小节）

报告主体要详尽展开。根据论文类型调整侧重（见 §5.2），保持四小节结构：

| 小节 | 目标 |
|------|------|
| ① 研究背景与问题 | 为什么重要、现有方法为什么不够好 |
| ② 方法方案 | 方法如何工作、每步设计动机 |
| ③ 实验效果 | 实验证明了什么、结果有多好、为什么好 |
| ④ 改进空间与展望 | 客观评价局限与合理改进方向 |

每个小节的详细涵盖项和写作要求见 `references/analysis-guide.md` §1.3。

#### 5.3.4 关键原图与图解

使用 §4.3 提取并重命名后的原论文图片，不使用 Mermaid 或任何凭空重绘的流程图。完整的嵌入格式、筛选规则和图解要求见 `references/analysis-guide.md` §1.4。

优先展示与论文类型相匹配、最能帮助理解的图片：

| 论文类型 | 优先展示的原论文图片 |
|----------|----------------------|
| 实验类（有训练） | 方法总览/模型架构、训练或推理流程、主结果、消融或定性案例 |
| 实验类（无训练） | 输入到输出的处理架构、关键模块、核心可视化结果 |
| 理论类 | 问题设定示意、直观解释图、关键实验或数值验证图 |
| 综述类 | 原文分类框架、时间线、领域概览图 |
| 系统类 | 系统架构、模块交互、性能和扩展性结果图 |

每张嵌入图片都应有准确图注，并紧随简短图解：说明它展示什么、读图顺序、与方法/实验结论的关系。非流程类图片只要确实能帮助理解，也应保留并展示；不为凑数重复嵌图。

#### 5.3.5 总结

使用 `> [!abstract] 论文总结` callout 收束全文，突出最重要的贡献和数据。

### 5.4 写作原则与讲解策略

> 写作原则、Callout 规范和五项增强讲解策略的完整说明见 `references/analysis-guide.md` §2-4。

**核心要求：**
- **把读者当作初学者** — 默认不假定读者认识该方向的缩写、基线、指标或常用模块。术语首次出现时先给出通俗定义和它在本文中的作用；按“问题与直觉 → 整体方案 → 模块细节/公式 → 实验如何验证”的顺序展开，避免只罗列结论或直接跳到实现细节。
- **宁深勿浅** — 每个关键技术点回答“它是什么、为什么需要它、具体如何工作、没有它会怎样/相对已有方法改进了什么”，并把解释落回论文证据。
- **原图辅助理解** — 对流程、架构、结构和结果，优先嵌入已提取的原论文图片并结合图注解读；图不适合或无法可靠提取时用文字说明，不生成 Mermaid 图。
- **事实优先** — 区分事实（"作者指出"）与推论（"可能暗示"），不要臆造
- **语言跟随用户** — 专业术语保留原文并附注释；`==高亮==` 关键术语和数字

### 5.5 检查清单

**基础检查：**
- [ ] 输入类型识别正确；多个候选论文已确认
- [ ] 论文类型判断明确
- [ ] 五段式结构完整：一句话总结→基本信息→核心详解→关键原图与图解→总结
- [ ] 核心详解四小节顺序正确（背景→方法→实验→展望）
- [ ] 关键结论客观真实，合理推断在语言表述上已清晰区分
- [ ] `==高亮==` 标记关键术语和核心数字
- [ ] Callout 使用规范
- [ ] 已从 PDF 提取图片，并将重要图片筛选、语义化重命名后保存至 `images/论文名/`
- [ ] 最关键的流程/架构原图已在 Markdown 中嵌入且与正文一致；若不存在或无法可靠提取，已用文字说明
- [ ] 其他确能帮助理解的图片（结果、消融、定性案例等）已按需嵌入并解读；未使用 Mermaid

**详细检查：**
- [ ] 方法部分每个关键组件解释了"为什么这样设计"
- [ ] 对比分析使用了结构化方式（表格/并列说明）
- [ ] 关键公式有符号解释和自然语言翻译
- [ ] 实验结果有深层解读（不只是数字，还有分析和洞察）
- [ ] 局限性有依据（论文提及或合理推断）
- [ ] 以初学者视角补足背景概念；首次出现的缩写、术语、指标和关键模块均已解释
- [ ] 方法、公式、原图和实验结果都说明了读法、作用与“为什么”，没有未经解释的推理跳步
- [ ] 未臆造实验数值、数据集或方法细节

## 6. 第五阶段：格式标准化与归档

对分析笔记进行元数据和格式标准化。详细操作模式（四种模式、标签映射、校验方式）见 `references/tidy-operations.md`。

### 6.1 标准格式框架

**Frontmatter：**

```yaml
---
title: "论文完整标题"
date: YYYY-MM-DD
tags:
  - paper/主题1
  - paper/主题2
aliases:
  - 简称1
  - 简称2
---
```

- `tags` 必须使用 `paper/xxx` 层级格式（如 `paper/vlm`、`paper/lora`）
- `aliases` 包含论文简称和其他常用提法
- `date` 为整理/创建日期

**正文结构：**

第一行在 frontmatter 之后：
```markdown
**原文**: [本地](论文/论文原件/文件名.pdf) [网络](https://arxiv.org/abs/XXXX.XXXXX)
```

然后按五段式结构组织正文。

### 6.2 核心原则

- **先读后改** — 修改前先读取受影响文件的 frontmatter 和正文结构。
- **先规划后执行** — 编辑前说明变更计划；用户提供明确映射表则跳过确认直接执行。
- **保留已有内容** — 格式标准化只补齐缺失结构和元数据，不重写用户已有分析。
- **批量编辑** — 多文件编辑尽量合并为少量 patch。
- **编辑后校验** — 在 frontmatter/正文结构语境中确认旧值已清除、新值已出现；无 `rg` 时用 `grep`/`find`。

### 6.3 工作流程

依次执行：①理解目标（范围/PDF/结构）→②发现并读取（文件查找与 Frontmatter）→③规划旧→新映射→④批量编辑→⑤搜索校验→⑥汇总变更统计。格式标准化不应新增 Mermaid 图；已有的原论文图片引用应保留并校验路径。

**步骤 1：理解目标状态** — 澄清范围（哪些文件/目录）、是否涉及 PDF 链接、是否需要标准化文档结构、是否需要补全论文基本信息表。

**步骤 2：发现并读取** — 查找 MD 文件（优先 `rg --files -g '*.md'`；不可用时用 `find`/Glob），并行读取 frontmatter 到第二个 `---` 结束标记，记录无 frontmatter 的文件，建立 MD ↔ PDF 映射表。

**映射规则：** `AI分析/` 目录下的 `.md` 文件 → `论文原件/同名.pdf`。文件名使用基于标题的简短命名（如 `MLP-Memory.md` ↔ `MLP-Memory.pdf`），简洁直观。

**步骤 3：规划变更** — 为每个文件构建旧→新映射，输出变更摘要（受影响文件数、标签映射、补充的 section 结构）。

**步骤 4：执行** — 批量编辑所有文件。小范围替换可精确改行；涉及结构补全或多字段重排时，替换完整 frontmatter/section 区块更稳。

**步骤 5：校验** — 两次搜索校验：旧值已消失、新值已出现。报告每个检查的通过/失败。

**步骤 6：汇总报告** — 输出变更统计表（目录/文件数/变更类型/状态）。

### 6.4 操作模式与注意事项

四种常见操作模式（A-添加原文 PDF 链接 / B-标签层级重构 / C-标准化文档结构 / D-清理冗余属性）的详细说明、标签映射表、校验方式和注意事项见 `references/tidy-operations.md`。

## 8. 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 检索结果太少（<3） | 放宽关键词或分类，扩大范围重检；若仍不足则分析已有论文并告知用户 |
| 检索结果过多 | 增加过滤条件，取 Top-15 供用户选择 |
| 论文无法通过 arxiv 下载 | 说明原因，提供链接建议用户手动获取 |
| 论文正文超长（50页+） | 优先分析方法与实验章节，概括相关工作与附录；报告开头标注"长篇论文，部分章节概括分析" |
| 仅能获取摘要 | 基于摘要生成初步分析并标注"[基于摘要分析]"，建议用户提供完整 PDF |
| 多篇论文同主题 | 逐篇生成独立分析报告，最后追加对比分析章节 |
| 用户未指定过滤条件 | 默认检索执行当天往前约 2 年的论文，按相关性排序，并写明实际日期范围 |
| 知识库目录不存在 | 询问用户知识库路径，或辅助创建标准目录结构 |
| 链接或搜索失败 | 说明失败原因，请求用户提供 PDF、arXiv ID 或更准确的标题 |
| 非学术论文 | 说明其非论文性质并询问是否继续分析 |
| 仅掌握摘要或片段 | 标注"基于部分内容分析"，建议用户提供完整论文 |

## 9. 优化拓展策略

### 批量处理
1. 按主题相关性排序，优先处理最相关的论文
2. 每篇论文独立走完下载→分析→整理流程
3. 所有论文完成后再生成汇总报告

### 论文质量标签
在筛选阶段为候选论文附加质量标签：
- **高影响力**：引用量高、来自顶会/顶刊
- **新工作**：近 1-2 年发表、方法新颖
- **有代码**：论文提供开源代码、可复现
- **综述类**：系统梳理领域进展

### 对比分析
多篇同主题论文时追加对比分析：
- 方法架构对比（使用原论文架构图，或以表格和文字对比）
- 性能数据对比表
- 创新点差异
- 适用场景建议

### 文献综述生成
用户选择"生成文献综述"时额外输出：
- 按时间线组织论文演进
- 归纳方法分类体系
- 指出研究空白与未来方向
- 输出为独立 MD 文件至 `论文/AI分析/`

### 引用关系探索
如可用，使用 citation graph / Semantic Scholar / Connected Papers 等引用关系工具探索重要相关工作和后续论文，构建研究脉络；不可用时用论文参考文献与主来源搜索兜底。
