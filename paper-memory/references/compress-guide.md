# 压缩指南

执行 `compress` 模式时使用本文档。它定义输出粒度并避免笔记膨胀。下述张量、损失和消融写法适用于计算/机器学习论文；其他类型按 [paper-types.md](paper-types.md) 映射到相同 Memory 章节。

## 1. 输出粒度

### 1.1 Flash Card（1 分钟复习）
用户明确要求快速复习或简短总结时使用。只保留：
- **一句话记忆**
- **研究问题**
- **核心洞察**
- **方法流程**
- **主要局限**

使用模板：[templates/flash-card.md](../templates/flash-card.md)

### 1.2 Standard Memory（默认）
适合长期保存到用户所选知识库的标准 Memory 格式。

使用模板：[templates/standard-memory.md](../templates/standard-memory.md)

### 1.3 Deep Memory
仅当用户明确要求深度分析、详细公式或代码映射时使用。在 Standard Memory 基础上增加：
- 关键数学公式（LaTeX 格式）和梯度信息
- 代码映射（伪代码或 PyTorch 风格的层结构）
- 详细的消融实验和超参数表
- 复现风险与超参数敏感度分析
- 深度关系分析

使用模板：[templates/deep-memory.md](../templates/deep-memory.md)

## 2. 各章节压缩规则

### 2.1 一句话记忆
- **要求**：必须同时覆盖：**研究问题** + **核心方法** + **主要作用/影响**。
- **禁止**：只复述标题或写"这篇论文是关于 X 的"。
- 好的例子："CLIP 通过在 4 亿互联网图文对上使用双塔对比损失预训练图像-文本编码器，实现了无需微调的零样本图像分类。"
- 坏的例子："CLIP: Learning Transferable Visual Models From Natural Language Supervision."

### 2.2 核心洞察
- **要求**：最多 3 条。
- **规则**：必须明确区分 **研究洞察**、**工程实现** 和 **普通组件**。
  - *研究洞察*：根本性的概念创新（如"自然语言可以作为可扩展的噪声监督信号来训练通用视觉模型"）。
  - *工程实现*：架构选择（如"双 ResNet/ViT 编码器通过对称对比损失对齐"）。
  - *普通组件*：标准骨干/工具（如"使用标准 Transformer 作为文本编码器"）。不能将使用常见 Backbone 视为论文的核心创新。

### 2.3 方法流程与图表引用规范
- **首选论文原图**：展示模型架构、算法流程或关键模块时，优先使用准确、可读且许可范围内可保存的论文原图；简化重绘更有助于理解时可以补充，但必须标为重绘或 AI 分析。
- **完整附件流程**：执行 [论文图片附件规范](attachment-guide.md)，包括矢量图页面渲染、裁剪、按 profile 落盘或上传、引用、迁移边界和可解析性验证。
- **首图嵌入**：若平台和 profile 允许，在元数据后嵌入最能概括整体方法的架构图；链接语法由 profile 决定。
- **局部图嵌入**：仅当局部图能独立解释粗检索、细定位或关键模块时，放到对应章节；不要把所有论文图表机械搬入笔记。
- **清理边界**：可清理本次提取产生且未采用的临时文件；既有未引用图片只报告，不自动删除。
- **文字兜底**：仅在完全无法获取或嵌入论文原图时，使用简短文本路径（输入 → 编码 → 对齐 → 损失函数 → 输出）补充说明。


### 2.4 关键模块
计算/ML 论文可按以下格式记录；其他论文把“模块”解释为关键论证、设计或证据环节：
```text
- 模块名称：
- 输入：张量维度和模态
- 输出：张量维度和模态
- 作用：计算什么
- 为什么需要：解决什么问题
- 去掉后可能发生什么：消融影响
```

### 2.5 核心公式
- **要求**：不要机械复制公式。只保留直接决定模型行为的公式。
- **LaTeX 格式**：行内公式用 `\(...\)` 或 `$...$`，块级公式用 `\[...\]` 或 `$$...$$`。
- **解释**：每个公式必须说明：
  1. 优化目标（最小化/最大化什么）。
  2. 正样本和负样本的定义。
  3. 关键变量的含义。
  4. 损失变化如何影响模型的特征空间。

### 2.6 实验证明了什么
- **要求**：不要堆积实验数字。
- **格式**：
  - **实验问题**：如"扩大数据集规模是否提升下游零样本分类性能？"
  - **比较对象**：基线和对比配置。
  - **观察结果**：高层结论（如"ViT-L 在 ImageNet 零样本上超过 ResNet-50 12%"）。
  - **支持的结论**：作者证明了什么。
  - **不能支持的结论**：未被证明的内容（如"不能证明在语言模板失效的严重分布外场景中的鲁棒性"）。
- **数字附带规则**：任何数字结果必须明确标注数据集、数据划分、评价指标和实验设置。

### 2.7 局限与失效场景
- **要求**：避免"计算量大""仍有提升空间"这类空泛描述。
- **格式**：
  - **局限**：具体的瓶颈或设计限制。
  - **产生原因**：为什么存在该限制。
  - **可能失败的场景**：具体的失败案例。
  - **对后续研究的意义**：后续工作如何解决。

## 3. Frontmatter 与标签生成规则

### 3.1 Frontmatter 填写规范
Memory 正文结构固定，但元数据结构由本地 profile 和目标平台决定。新资料库尚无偏好时，可建议以下最小集合：
- `title`：论文的完整标题。
- `date`：论文发表的年份或具体日期（YYYY 或 YYYY-MM-DD）。
- `tags`：分类标签列表（使用下方的推荐命名空间标签）。
- 不删除 profile 未明确禁止的既有字段。Obsidian 可使用 frontmatter，Notion 应映射到 database properties，普通 Markdown 也可以不用 YAML。

### 3.2 标签规范
标签用于宽分类，不应取代双向链接。

标签语言、命名空间和数量遵循 profile。若 profile 采用本 Skill 的推荐分类法，再使用中文命名空间 `论文/...`、`方法/...`、`任务/...`、`模态/...`。

生成标签前必须阅读并执行 [tag-taxonomy.md](tag-taxonomy.md)，尤其检查同义标签、跨命名空间同叶标签，以及领域与任务的重复表达。

### 3.3 文件命名
文件或页面命名遵循 profile。尚无既有规则时，可建议使用短名称：`CLIP.md`、`DINOv2.md`、`Text2Loc.md`。

如果存在重名，使用 `论文短名-年份.md` 格式，例如：`ALIGN-2021.md`。

不要默认使用过长的完整论文标题作为文件名。
