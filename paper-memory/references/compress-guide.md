# 压缩指南

执行 `compress` 模式时使用本文档。它定义了输出粒度并提供内容提取规则，避免笔记膨胀。

## 1. 输出粒度

### 1.1 Flash Card（1 分钟复习）
用户明确要求快速复习或简短总结时使用。只保留：
- **一句话记忆**
- **研究问题**
- **核心洞察**
- **方法流程**
- **主要局限**

使用模板：[templates/flash-card.md](../templates/flash-card.md)

### 1.2 Standard Memory（默认）
适合长期保存到 Obsidian 的标准笔记格式。

使用模板：[templates/standard-memory.md](../templates/standard-memory.md)

### 1.3 Deep Memory
仅当用户明确要求深度分析、详细公式或代码映射时使用。在 Standard Memory 基础上增加：
- 关键数学公式（LaTeX 格式）和梯度信息
- 代码映射（伪代码或 PyTorch 风格的层结构）
- 详细的消融实验和超参数表
- 复现风险与超参数敏感度分析
- 深度关系分析

使用模板：[templates/deep-memory.md](../templates/deep-memory.md)

## 2. 各章节压缩规则

### 2.1 一句话记忆
- **要求**：必须同时覆盖：**研究问题** + **核心方法** + **主要作用/影响**。
- **禁止**：只复述标题或写"这篇论文是关于 X 的"。
- 好的例子："CLIP 通过在 4 亿互联网图文对上使用双塔对比损失预训练图像-文本编码器，实现了无需微调的零样本图像分类。"
- 坏的例子："CLIP: Learning Transferable Visual Models From Natural Language Supervision."

### 2.2 核心洞察
- **要求**：最多 3 条。
- **规则**：必须明确区分 **研究洞察**、**工程实现** 和 **普通组件**。
  - *研究洞察*：根本性的概念创新（如"自然语言可以作为可扩展的噪声监督信号来训练通用视觉模型"）。
  - *工程实现*：架构选择（如"双 ResNet/ViT 编码器通过对称对比损失对齐"）。
  - *普通组件*：标准骨干/工具（如"使用标准 Transformer 作为文本编码器"）。不能将使用常见 Backbone 视为论文的核心创新。

### 2.3 方法流程与图表引用规范
- **首选论文原图**：在展示模型架构、算法流程或其他插图时，**尽量使用论文中的原始插图，不要自行使用 Mermaid 绘制流程图**。
- **获取原图的最佳实践**：
  1. **防止矢量图遗漏**：LaTeX 导出的 PDF 中，架构图/流程图通常由矢量路径和文本组合而成，并非单一的图片对象。直接用 API 提取图片对象（如 `pypdf` 的 `page.images`）往往只会提取到背景栅格（如散点图、点云三维图等），会遗漏关键流程图。
  2. **高分辨率页面渲染**：必须使用 PDF 渲染库（如 `pypdfium2`，设置 `scale=3` 或更高）将包含关键图表的页面渲染为高分辨率 PNG 图像。
  3. **定位与裁剪**：在渲染出的页面图像中，定位图题文本（例如 "Figure 2"、"Figure 3"）的坐标，并将对应的图像区域（**包括流程图本身和图题说明文本**）完整裁剪出来，以确保图表具有独立可读性。
- **图片存放路径**：所有的论文图片必须统一存放在 Obsidian 仓库根目录下的 `images/论文短名/` 目录下（例如：`images/CLIP/fig2_overview.jpg`）。
- **引用与排版格式**：
  - **首图嵌入**：在 Markdown 笔记的最上方（Frontmatter 下方）嵌入整体架构图（例如 `![[images/论文短名/fig2_overview.jpg]]`）。
  - **局部图嵌入**：在具体的“方法流程”子章节（如粗检索、细定位）和“关键模块”子章节下，亦应分别嵌入对应的局部流程图或模块流向图，避免只在开头放一张图。
  - 标准 Markdown 格式：`![方法流程](images/论文短名/图片名.png)` 或 Obsidian 内部链接格式：`![[images/论文短名/图片名.png]]`。
- **清理无用图片，防止仓库膨胀**：
  在裁剪、重命名并关联图片后，**必须删除所有在 Markdown 笔记中未被引用或非核心的无用图片**（例如介绍性插图、实验效果定性对比散点图、t-SNE 可视化图等不影响理解模型结构的核心图表）。整个 `images/论文短名/` 目录下**只应保留在笔记中实际被引用的、最具代表性的结构图与流程图**。
- **文字兜底**：仅在完全无法获取或嵌入论文原图时，才可使用简短的文本路径（如：输入 → 编码 → 对齐 → 损失函数 → 输出）进行补充说明，禁止自行生成繁琐的 Mermaid 图。


### 2.4 关键模块
对每个独特或核心模块，严格按以下格式记录：
```text
- 模块名称：
- 输入：张量维度和模态
- 输出：张量维度和模态
- 作用：计算什么
- 为什么需要：解决什么问题
- 去掉后可能发生什么：消融影响
```

### 2.5 核心公式
- **要求**：不要机械复制公式。只保留直接决定模型行为的公式。
- **LaTeX 格式**：行内公式用 `\(...\)` 或 `$...$`，块级公式用 `\[...\]` 或 `$$...$$`。
- **解释**：每个公式必须说明：
  1. 优化目标（最小化/最大化什么）。
  2. 正样本和负样本的定义。
  3. 关键变量的含义。
  4. 损失变化如何影响模型的特征空间。

### 2.6 实验证明了什么
- **要求**：不要堆积实验数字。
- **格式**：
  - **实验问题**：如"扩大数据集规模是否提升下游零样本分类性能？"
  - **比较对象**：基线和对比配置。
  - **观察结果**：高层结论（如"ViT-L 在 ImageNet 零样本上超过 ResNet-50 12%"）。
  - **支持的结论**：作者证明了什么。
  - **不能支持的结论**：未被证明的内容（如"不能证明在语言模板失效的严重分布外场景中的鲁棒性"）。
- **数字附带规则**：任何数字结果必须明确标注数据集、数据划分、评价指标和实验设置。

### 2.7 局限与失效场景
- **要求**：避免"计算量大""仍有提升空间"这类空泛描述。
- **格式**：
  - **局限**：具体的瓶颈或设计限制。
  - **产生原因**：为什么存在该限制。
  - **可能失败的场景**：具体的失败案例。
  - **对后续研究的意义**：后续工作如何解决。

## 3. Frontmatter 与标签生成规则

### 3.1 Frontmatter 填写规范
为了保持笔记整洁并与现有知识库样式对齐，Frontmatter 应保持极简，仅包含以下三个基础属性：
- `title`：论文的完整标题。
- `date`：论文发表的年份或具体日期（YYYY 或 YYYY-MM-DD）。
- `tags`：分类标签列表（使用下方的推荐命名空间标签）。
- 不使用 `aliases`。论文简称由简洁文件名和正文 Wiki 链接表达，避免同一简称解析到多个文件。
- 注意：所有其他冗余属性（如 `status`、`review_count` 等）均无需塞入 Frontmatter，以保持笔记格式极简和统一。

### 3.2 标签规范
标签用于宽分类，不应取代双向链接。

默认使用中文命名空间：`论文/...`、`方法/...`、`任务/...`、`模态/...`。一篇论文通常保留 3–6 个有区分度的标签，不为了凑数量加入宽泛标签；Transformer、BEV、LoRA 等通用专名可保留英文。

生成标签前必须阅读并执行 [tag-taxonomy.md](tag-taxonomy.md)，尤其检查同义标签、跨命名空间同叶标签，以及领域与任务的重复表达。

### 3.3 文件命名
默认使用短名称：`CLIP.md`、`DINOv2.md`、`Text2Loc.md`。

如果存在重名，使用 `论文短名-年份.md` 格式，例如：`ALIGN-2021.md`。

不要默认使用过长的完整论文标题作为文件名。
