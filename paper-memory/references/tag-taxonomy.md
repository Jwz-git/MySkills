# 标签分类与语义去重规范

在创建论文笔记、更新 Frontmatter 或批量整理论文库标签时使用本规范。目标不是逐字翻译旧标签，而是建立可筛选、低冗余、语义边界稳定的标签体系。

## 1. 默认语言与命名空间

默认使用中文四维命名空间：

| 命名空间 | 回答的问题 | 适合的值 | 不应放入 |
| --- | --- | --- | --- |
| `论文/...` | 这篇论文属于什么研究领域或文献类型？ | `视觉语言`、`三维视觉`、`计算机视觉`、`大语言模型`、`综述` | 已由任务表达的 `定位`、`检索` |
| `方法/...` | 核心机制或技术路线是什么？ | `对比学习`、`自蒸馏`、`对称池化`、`参数高效微调` | 过宽且不能区分论文的方法词 |
| `任务/...` | 论文直接解决什么问题？ | `检索`、`定位`、`分类`、`表征学习` | 数据形式或研究领域 |
| `模态/...` | 输入、输出或主要数据形态是什么？ | `图像`、`图文`、`点云`、`文本`、`多模态` | 方法名称或任务名称 |

叶标签尽量使用中文。Transformer、BEV、LoRA、MLP 等已形成稳定用法的专名可保留英文。已有知识库若明确采用另一套语言规范，优先保持全库一致；不要在同一目录混用 `paper/` 与 `论文/` 等两套命名空间。

## 2. 标签数量与选择

一篇论文通常保留 3–6 个标签：

- 1 个主要 `论文/...` 标签；确有必要时可增加一个文献类型或交叉领域标签。
- 1–2 个能区分论文的 `方法/...` 标签；没有可靠、具体的方法标签时宁可省略。
- 1 个主要 `任务/...` 标签；论文确实覆盖多个独立任务时可增加。
- 仅添加检索时有价值的 `模态/...` 标签。

不要为了满足数量而加入“深度学习”“神经网络”“表征学习”等过宽标签，也不要把每个关键词都变成标签。论文之间的具体继承、改进和对比关系使用 Wiki 链接表达。

## 3. 语义去重流程

批量整理时，先读取目标目录内所有 Markdown 文件的完整 Frontmatter，再执行以下步骤：

1. 汇总唯一标签、出现频次和对应文件，记录无 Frontmatter、无 `tags` 或格式异常的文件。
2. 统一语言、大小写、单复数和拼写变体，例如 `paper/vision-language` 与 `论文/视觉语言` 归入同一中文规范。
3. 合并同一维度内的真正同义标签；合并后同一文件只保留一次。
4. 检查相同叶标签是否分散在不同命名空间。选择最能回答其分类问题的唯一维度，不要仅因前缀不同就同时保留。
5. 对宽泛标签，优先删除或替换为已有材料能直接支持的具体标签；不能从标题、摘要、正文或可靠来源确认时，不自行补造。
6. 编辑前给出简短映射摘要；编辑时只改 Frontmatter 并保留原 YAML 风格；编辑后再次审计。

### 跨维度重名的处理

- `论文/定位` + `任务/定位`：保留 `任务/定位`；`论文/...` 改为 `三维视觉`、`计算机视觉` 等更宽的研究领域。不要在同一篇笔记中保留两者。
- `方法/表征学习` + `任务/表征学习`：判断“表征学习”在该文中是研究目标还是具体机制。若已有更具体的方法标签（如 `方法/对比学习`），删除宽泛的 `方法/表征学习`；否则依据正文选用一个维度。
- `论文/多模态` + `模态/多模态`：前者表示研究领域，后者表示数据形态。若论文实际属于更明确的视觉语言领域且已有 `模态/图文`，优先使用 `论文/视觉语言` + `模态/图文`。

## 4. 不要误合并相关概念

相似或存在上下位关系不代表同义：

- `任务/定位`：一般定位任务。
- `任务/地理定位`：推断全球地理位置或区域。
- `任务/地点识别`：将查询与已知地点数据库匹配，常见于 VPR。

除非用户明确要求建立更深层级，否则保留这些有独立筛选价值的标签。其他概念也按“能否互换且不改变论文含义”判断；只能互相关联、不能互换的标签不合并。

## 5. 推荐示例

```yaml
# CLIP
tags:
  - 论文/视觉语言
  - 方法/对比学习
  - 任务/检索
  - 模态/图文

# Text2Loc
tags:
  - 论文/三维视觉
  - 方法/对比学习
  - 任务/定位
  - 模态/点云

# PointNet
tags:
  - 论文/三维视觉
  - 方法/对称池化
  - 任务/分类
  - 模态/点云
```

Text2Loc 不再额外添加 `论文/定位`；PointNet 不使用过宽的 `方法/表征学习`，因为笔记材料已支持更具体的 `方法/对称池化`。

## 6. 修改后验证

批量修改后运行：

```bash
python scripts/audit_tags.py /path/to/paper-notes --strict-cross-namespace
```

完成标准：

- 所有目标文件的 Frontmatter 结构可识别。
- 同一文件内没有重复标签。
- 不再残留英文命名空间。
- 没有未经解释的跨命名空间同叶标签。
- Frontmatter 中不存在 `aliases`。
- 正文、标题和文件名未因标签整理被误改。
- 汇总修改文件数、标签总数、唯一标签数及旧值残留检查结果。

`audit_tags.py` 负责标签结构和一致性检查，不等价于完整 YAML 解析器；环境提供 YAML 解析库时，再补充一次 YAML 语法解析。
