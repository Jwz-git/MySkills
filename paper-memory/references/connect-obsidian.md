# Obsidian 双向链接指南

执行 `connect` 模式时使用本文档。它定义了论文链接、关系分类、反向链接更新和 MOC 页面管理的规则。

## 1. 关系类型

连接两篇论文时，使用以下严格定义的关系类别：

| 关系键 | 中文展示 | 语义定义 |
| --- | --- | --- |
| `builds-on` | 建立在……基础上 | 直接后继，使用前作的核心范式。 |
| `improves` | 改进…… | 针对前作的特定弱点进行优化或修复。 |
| `extends-to` | 扩展到…… | 将已有方法应用到新的模态或任务领域。 |
| `replaces` | 替代…… | 在特定任务上全面超越并替代前作。 |
| `uses-as-backbone` | 使用……作为骨干网络 | 使用前作的模型/编码器作为主要特征提取器。 |
| `uses-as-loss` | 使用……的训练目标 | 使用另一篇论文提出的损失函数。 |
| `same-task` | 任务相同 | 解决相同的核心问题，但使用不同的方法。 |
| `similar-idea` | 思想相似 | 概念上有重叠或平行发现，但无直接继承关系。 |
| `complements` | 能力互补 | 协同方法，可以组合使用以获得更好的结果。 |
| `contradicts` | 结论存在冲突 | 呈现对立的发现、假设或评估。 |

## 2. Obsidian 链接格式

- **规则 1**：始终使用 Obsidian Wiki Link 格式：`[[论文名]]`。
- **规则 2**：在书写 Wiki 链接时，**绝对禁止在链接两侧包裹反引号（Backticks）**（例如不要写成 `` `[[CLIP]]` ``），因为这会导致其被渲染为代码块，使链接无法正常跳转；同时，**绝对禁止在链接目标中包含 `.md` 后缀**（例如不要写成 `[[CLIP.md]]`），这会导致 Obsidian 无法正确建立关联图谱。正确示例：`[[CLIP|CLIP多模态预训练]]` 或 `[[SpatiaLoc]]`。
- **规则 3**：引用有对应笔记（或应该有笔记）的论文时，绝不使用纯文本（如"CLIP"）。
- **规则 4**：文件命名使用短名称：`CLIP.md`、`DINOv2.md`。名称冲突时追加年份：`ALIGN-2021.md`。

## 3. 双向（反向）链接更新

每次从论文 A 添加指向论文 B 的链接时，都必须处理反向链接。

- **示例**：如果 `VLM-Loc.md` 中添加了 `VLM-Loc builds-on CLIP`，必须生成：
  1. **当前文件更新**：在 `VLM-Loc.md` 中添加 `builds-on [[CLIP]]`。
  2. **反向更新建议**：指出 `CLIP.md` 中的对应修改（例如，在其"后续应用或改进"章节中添加 `[[VLM-Loc]]`）。
- **执行方式**：如果有目标笔记文件的写入权限，安全地同时更新两个文件。如果没有写入权限，输出明确的补丁建议，方便用户复制粘贴。

## 4. MOC（Map of Content）页面设计

MOC 作为研究领域的导航入口。不要在 MOC 中复制论文摘要。

### 4.1 目录和文件命名
将 MOC 页面放在专用目录中：
```text
MOCs/
├── Vision-Language.md
├── 3D-Language-Localization.md
├── Contrastive-Learning.md
└── BEV-VLM.md
```

### 4.2 模板结构
MOC 文件应遵循 [templates/moc-template.md](file:///Users/jwz/.agents/skills/paper-memory/templates/moc-template.md) 的布局，必须包含：
1. **标题**：领域/主题名称。
2. **基础表示与基线**：核心理论/模型基础（使用 Wiki Link）。
3. **核心工作与演进**：按子主题分组的文献列表。
4. **关键研究挑战**：共同的科学瓶颈。
5. **研究空白与机会**：未来研究方向。

---

## 5. 图谱设计原则
防止 Obsidian Graph View 变成毫无意义的混乱"毛线球"：
- **禁止表层连接**：不要仅仅因为"两篇论文都用了 PyTorch""都用了 Transformer"或"都发表于 2024 年"就建立链接。
- **可操作性**：每条链接都必须代表有意义的研究思想传承。自问：*知道这条链接是否有助于研究者设计更好的实验或写更强的文献综述？* 如果答案是否，则省略该链接。

## 6. 关系段落格式示例

以下是一个完整的论文关系段落示例，展示了正确的格式化方式：

### 示例：VLM-Loc.md 中的关系段落

```markdown
# 与其他论文的关系

## 前置基础
- [[CLIP]]：提供跨模态对比学习和共享 embedding 空间。
- [[PointNet]]：提供直接处理无序点云的基础编码思想。

## 同任务工作
- [[Text2Loc]]：同样研究语言驱动的地点定位，但表示和精细定位方式不同。

## 后续改进
- [[VLM-Loc]]：在语言定位中进一步引入 VLM 表示能力。

## 关键差异
与 [[CLIP]] 相比，本方法不只要求语义对齐，还需要保持空间和几何关系。
```

注意要点：
- 每条关系使用 `[[Wiki Link]]` 格式
- 冒号后简要说明关系内容
- 不使用纯文本论文名
