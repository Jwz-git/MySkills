# 证据与可靠性规则

在执行 `paper-memory` 的所有模式时，使用本文档作为严格的验证框架。它确保事实信息与推测以及 AI 推断明确区分开来。

## 1. 内容分类

为防止在查看旧笔记时产生认知混淆，将内容明确分为以下四个领域：

### 1.1 论文事实 (Paper Facts)
- **定义**：明确写在论文正文、附录或官方 GitHub 代码仓库中的信息。
- **标记/样式**：使用肯定的语言，如果可行，标注页码或章节号。
- **示例**：CLIP 使用的文本编码器是用包含 12 层和 8 个注意力头的 63M 参数 Transformer 初始化的。

### 1.2 用户理解 (User Understanding)
- **定义**：用户的个人理解、心智模型或对概念的主观重构。
- **标记/样式**：在前面添加或标记 `[用户理解]` 或 “用户认为……”。
- **示例**：`[用户理解]` 感觉 CLIP 的温度参数 \(\tau\) 起到了软阈值的作用，迫使模型优先对齐高置信度的对齐。

### 1.3 AI 分析 (AI Analysis)
- **定义**：AI 根据论文内容和提示词上下文做出的逻辑归纳、总结、比较或背景关联。
- **标记/样式**：在前面添加或标记 `[AI分析]` 或 “AI 分析认为……”。
- **示例**：`[AI分析]` CLIP 对大 batch size (32k) 的依赖至关重要，因为对比学习指标直接随着负样本候选的数量缩放。

### 1.4 待验证假设 (Hypotheses to Validate)
- **定义**：开放性问题、潜在问题或需要未来进一步验证的实验假设（无论是通过阅读后续论文还是通过运行实验）。
- **标记/样式**：在前面添加或标记 `[待验证]` 或 “待验证假设：……”。
- **示例**：`[待验证]` 如果在低分辨率、严重失真的医学图像上评估，CLIP 的零样本性能会显著下降吗？

## 2. 缺失信息的处理

> [!CAUTION]
> **严禁编造论文实验、数据指标或代码实现细节。**

如果论文或提供的上下文中没有提到某个细节，按以下步骤处理：
1. **绝不猜测或推断**数值或结果。
2. 明确使用以下三种占位符之一：
   - **当前材料无法确认** —— 当提示词中提供的源文本不完整时。
   - **论文未报告** —— 当作者没有在论文中包含该细节时。
   - **尚未核验** —— 当提出了某项声称但尚未与代码或附录内容核对时。
3. 保持目标字段为空，或在 frontmatter 中明确注明缺失细节，不要生造。
