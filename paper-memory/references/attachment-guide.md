# 论文图片附件规范

在创建、更新、提取或迁移论文图片时使用本文档。本文只管理图片；PDF 原文继续使用 profile 中的论文原件位置。下述 `assets/<noteFileName>/` 是适用于本地 Markdown/Obsidian 的推荐方案，只有 profile 采用该布局时才是要求；Notion 或其他平台应使用其附件机制并验证引用可访问。

## 1. 目标布局

本地 profile 未发现既有约定时，可以向用户建议笔记同级、按笔记名隔离的目录：

```text
<笔记所在目录>/
├── CLIP.md
└── assets/
    └── CLIP/
        ├── fig1_overview.jpg
        └── fig2_training.png
```

目标目录由以下表达式确定：

```text
<noteDir>/assets/<noteFileName>/
```

其中 `<noteFileName>` 是不含 `.md` 的文件名。仅当 profile 使用该 pattern 时，`./` 才相对于当前笔记目录。

如果 Vault 安装了 Custom Attachment Location：

1. 读取 `.obsidian/plugins/obsidian-custom-attachment-location/data.json`。
2. 当 `attachmentFolderPath` 为 `./assets/${noteFileName}` 时，直接使用上述布局。
3. 若用户已有不同配置，先报告差异；不要静默修改插件配置或把现有附件迁移到另一套规则。

## 2. 链接格式

当 profile 的 `attachments.link_style` 为 `markdown` 时使用：

```markdown
![CLIP 训练与零样本分类流程](./assets/CLIP/fig1_overview.jpg)
```

规则：

- 若 profile 选择标准 Markdown，则不混用 Obsidian 专有图片嵌入 `![[...]]`；其他链接风格按 profile 验证。
- 使用从笔记到图片的相对路径；profile 的 pattern 含 `./` 时显式保留。
- alt 文本描述图片内容，不只写“图片”或机械复制文件名。
- 文件名优先使用稳定、可读的 `figN_简短说明.ext`；不要仅使用时间戳命名。
- 图片链接与论文关系链接分别遵循 `attachments.link_style` 和 `links.style`，不要互相套用语法。

## 3. 原图提取

架构图和流程图优先使用论文原图：

1. 先定位图号、图题和所在页。
2. PDF 中的关键图可能由矢量路径与文本组合而成。图片对象提取不完整时，使用 `pypdfium2` 等渲染器按 `scale=3` 或更高渲染整页。
3. 适当裁剪，而不是保存整页：
   - 去除页眉、页脚、页码、周围正文和不影响理解的大块空白。
   - 保留完整图形、所有子图、图例、坐标轴、箭头、模块文字、子图编号，以及足以独立理解图片的图题。
   - 四周保留少量安全边距，避免文字或线条贴边；不要为了画面紧凑切掉图例、标注或图题。
   - 若图题与图片跨栏、跨页或相距过远，优先保证图形完整，并在 Markdown alt 文本或正文中补充图号和含义，不拼接会误导读者的区域。
4. 裁剪后必须视觉复核原始分辨率图片，确认文字可读、内容完整、没有混入相邻图表；不能仅凭自动坐标或文件生成成功判断质量。
5. 先写入任务临时目录；确认图片核心、清晰且将被引用后，再移动到目标附件目录。
6. 同一笔记只保留帮助理解研究问题、总体流程或关键模块的核心图片，不为凑数量保存装饰性插图。

## 4. 迁移既有图片

迁移前先做只读清单，至少区分：

- 已引用且只属于一篇笔记的图片；
- 被多篇笔记共享的图片；
- 未引用图片；
- 无法解析或目标不存在的链接。

执行规则：

1. 只自动迁移“已引用且只属于一篇笔记”的图片。
2. 共享图片默认保留原位并报告；是否复制到各笔记目录由用户或插件的共享附件策略决定。
3. 既有未引用图片保留原位并报告，不把“未引用”等同于“可删除”。
4. PDF、PPT、数据文件等非图片附件不参与仅图片迁移。
5. 移动前检查目标文件是否存在；同名但内容不确定时停止并报告冲突，不覆盖。
6. 移动图片后，在同一操作中把引用更新为 profile 规定的链接格式。

## 5. 清理边界

可以直接删除的内容仅限本次任务创建、且已确认不会使用的临时渲染页和临时裁剪图。对于任务开始前已存在的文件：

- 不因“看起来不重要”而删除；
- 不因当前没有 Markdown 引用而删除；
- 将候选孤立图片、位置和判断依据报告给用户，由用户决定是否清理。

## 6. 完成验证

完成前执行可复核检查：

1. profile 使用本地 Markdown 推荐布局时，迁移或批量整理优先运行 `scripts/audit_image_attachments.py <memory-root>` 获取只读基线，并在操作后再次运行；其他平台使用对应的只读审计方法。
2. 统计移动的唯一图片数、修改的笔记数和图片引用总数。
3. 对每个本地图片链接，验证目标文件存在。
4. 验证每张已迁移图片的父目录等于 `root_pattern` 展开后的目录。
5. 仅当 `attachments.link_style: markdown` 时，将目标范围内的 `![[图片]]` 报告为格式不一致；选择 Wiki 图片时不报错。
6. 对新裁剪图片做视觉复核，检查文字可读性、完整性、安全边距和相邻内容污染。
7. 再次报告共享图片、未引用图片和未解析链接；它们不应被静默处理。
8. 确认 PDF 和其他非图片附件没有移动。

交付时分别报告“观察到的数量”“执行的移动/修改”“验证结果”和“保留未处理的例外”，不要只说“迁移完成”。
