# 主动回忆复习指南

执行 `review` 模式时使用本文档。核心规则：**绝不先展示论文摘要或答案。** 必须通过主动回忆对话来引导用户。以下结构问题以计算论文为例；其他论文按 [paper-types.md](paper-types.md) 替换问题语义，阶段和评分结构保持不变。

## 0. 复习前准备

在开始复习会话之前：
1. **定位 Memory**：根据 profile 在 Memory 根目录、Notion database 或等价容器中查找对应条目。
2. **加载 Memory 内容**：读取找到的内容，将其作为评分和反馈的依据。
3. **如果找不到笔记**：告知用户尚未找到该论文的记忆笔记，建议先使用 `compress` 模式创建笔记，再进行复习。
4. **检查复习历史**：仅当 profile 配置了复习记录持久化时，从指定位置读取历史；不要假定 frontmatter 一定含有 `review_count` 或 `last_reviewed`。

---

## 1. 四阶段复习流程

当用户请求复习（如"复习 CLIP"或"考考我这篇论文"）时，按以下四个阶段逐步引导用户：

```text
阶段一：自由回忆
  ↓
阶段二：结构回忆
  ↓
阶段三：机制理解
  ↓
阶段四：批判与迁移
```

### 阶段一：自由回忆
- **提问**：
  > 请不用看笔记，用一句话说明这篇论文解决什么问题，以及核心方法是什么。

### 阶段二：结构回忆
针对论文的方法或论证结构提出具体问题。计算论文可以问：
- 模型的输入和输出分别是什么？训练阶段和推理阶段有何不同？
- 使用了哪些编码器或骨干网络？
- 各模态在哪里以及如何交互或对齐？
- 损失函数是什么？
- 推理阶段如何工作（如零样本预测流程）？

### 阶段三：机制理解
通过设计原理的深入提问来加深理解：
- 作者为什么选择这种对齐方法而非其他替代方案？
- 模块 X 具体解决什么问题？去掉它会怎样？
- 这种方法依赖哪些隐含的或未说明的假设？

### 阶段四：批判与迁移
将论文与用户自身的研究联系起来：
- 这种方法能否迁移到你当前的研究课题？如何迁移？
- 哪些具体组件可以直接复用，哪些必须修改？
- 你会设计什么实验来验证这种迁移？

---

## 2. 反馈格式

用户回答每个阶段的问题后，在进入下一阶段前提供建设性反馈。使用以下固定格式：

```text
掌握正确：[用户回答正确的内容]
遗漏内容：[用户遗漏的关键细节]
存在混淆：[用户表述中的误解或错误事实]
建议复习：[建议复习的笔记具体章节]
下一题：[下一阶段的问题]
```

---

## 3. 评分系统（10 分制）

会话结束时，生成评分卡评估用户的记忆水平。不要只输出总分，必须按维度拆分：

- **研究问题**：0 到 2 分。（对论文目标问题和基线局限的理解。）
- **核心思想**：0 到 2 分。（对核心创新和洞察的理解。）
- **方法流程**：0 到 2 分。（对输入输出、结构和损失的理解。）
- **实验理解**：0 到 2 分。（对基线、数据集和局限的回忆。）
- **批判与迁移**：0 到 2 分。（评估局限、迁移概念到自身任务和设计实验的能力。）

### 最终评分卡格式
```markdown
### 复习得分总结

| 维度 | 得分 | 表现分析 |
| --- | --- | --- |
| 研究问题 | /2 | |
| 核心思想 | /2 | |
| 方法流程 | /2 | |
| 实验理解 | /2 | |
| 批判与迁移 | /2 | |
| **总分** | **/10** | |

**薄弱点记录**：
- [用户困难的具体组件或模块]
- [后续建议，如"重新阅读 CLIP 的消融实验"]
```

### 更新元数据
复习结束后，仅在 profile 配置允许且用户授权写入时，按 `review.persistence` 更新复习记录。若未配置持久化，只在会话中输出评分卡。
