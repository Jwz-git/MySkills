# 边界情况处理指南

本文档说明 img2md 在遇到特殊图片类型和多图输入时的处理方式。

## 多图批量输入

当前版本一次处理一张图片。如果用户上传了多张图片：

1. **逐个处理**：对每张图片分别运行 `prepare_image.py`，分别提取内容
2. **分别输出**：每张图片生成独立的 Markdown 文件，保存到 `/workspace/`
3. **文件命名**：如果多张图片属于同一文档（如多页扫描件），在文件名中添加页码，如 `报告_第1页.md`、`报告_第2页.md`
4. **提示用户**：处理完成后告知用户生成了多个文件

如果用户明确要求合并为一份文档，则按顺序拼接所有图片的内容，输出为一个文件。

## GIF 动图

- **只处理第一帧**：GIF 动图只提取第一帧的内容
- **标注说明**：在输出文件末尾添加注释说明这是 GIF 的第一帧

```markdown
# [提取的内容]

<!-- 注：此内容提取自 GIF 动图的第一帧 -->
```

## 多页 TIFF

- **逐页处理**：多页 TIFF 的每一页都单独提取
- **分别输出**：每页生成独立文件，文件名带页码（如 `文档_第1页.md`）
- **合并选项**：如果用户要求，可以合并为一个文件，页与页之间用 `---` 分隔

## 深色背景 / 低对比度图片

裁剪算法已内置自适应阈值，能自动适应不同对比度的图片。但如果图片质量极差（如严重模糊、过度曝光），可能导致：
- 文字识别困难 → 使用 `[unclear]` 标记
- 裁剪位置不理想 → 脚本会尽量避开文字区域，极端情况下可能无法完美避开

## 超大图片

对于宽度或高度极大的图片（如超过 10000px）：
- 脚本仍会正常处理，但可能消耗较多内存
- 如果内存不足导致失败，提示用户先压缩图片再重试

## 纯空白图片

如果图片完全空白（无任何文字或视觉内容）：
```markdown
# 图片内容

> [空白图片]
> 此图片不包含任何可提取的文字或视觉内容。
```

## 加密 / 受保护的图片

如果图片被加密、有 DRM 保护或无法正常打开：
- 在输出中说明情况，不要尝试绕过保护机制
- 建议用户提供未加密的版本
