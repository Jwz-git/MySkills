# 边界情况处理

只在遇到对应输入时读取本文件。

## 多图输入

- 明显属于同一文档的连续页：按用户提供顺序合并为一个 Markdown；可用 `<!-- 第 N 页 -->` 标记页界，但不要重复页眉页脚。
- 互不相关的图片：分别输出 Markdown。
- 顺序或分组无法从文件名、上传顺序和内容判断，且会改变结果：再询问用户。
- 每张原图都单独运行 `prepare_image.py`，不要只处理第一张。

## 长图与重叠分片

`prepare_image.py` 会把高度超过阈值的图片分成带重叠区域的片段。读取全部 `files_to_read` 后：

1. 用相同的完整句、表格行或代码行定位重叠区；
2. 只删除能确认完全重复的内容；
3. 不能确认时保留并加 `<!-- possible overlap -->`，不要猜测衔接文本；
4. 需要裁剪视觉元素时优先使用原图坐标，而不是分片坐标。

## GIF 动图

默认只转录第一帧，`notes` 会报告总帧数。若用户明确要求全部帧，逐帧导出后按时间顺序处理；不要把多个帧之间的变化臆测成文字或事件。

文件交付模式下可在文末注明：

```markdown
<!-- 来源为动画 GIF；本次仅转录第一帧。 -->
```

## 多页 TIFF

脚本会把每页展开为 PNG，并把页面或页面分片按顺序写入 `files_to_read`。默认合并为一个 Markdown；页与页之间只有在内容边界不清时才使用 `---`。

## 旋转、透视与镜像

- 先检查 EXIF 方向是否已由读取工具应用。
- 文字明显旋转时，在不覆盖原文件的前提下生成校正副本再读取。
- 文档照片有透视畸变时，可以先校正副本，但不能用几何校正补出原图中不存在的像素细节。
- 镜像文字只有在方向可确认时纠正读取方向；转录内容本身不加“修正后的”猜测。

## 深色背景、低对比度与模糊

分片算法只用于寻找裁剪位置，不是 OCR 引擎，也不能证明文字可读。若文字仍不可辨：

- 完全无法确认：`[unclear]`
- 仅能确认一部分：`[partially visible: 可确认部分]`
- 被覆盖或截断：`[obscured]`

不要根据上下文补字。可以在最终交付中报告不确定标记数量。

## 超大图片

若内存不足，先创建等比例缩小的临时副本用于全局定位，再从原图分区裁剪读取。不要覆盖原图；不要让缩小副本成为最终嵌入资源，除非用户更重视体积。

## 空白图与纯照片

- 真正空白：输出 `> [空白图片：未检测到可转录文字或有语义的视觉内容]`。
- 纯照片：不是空白。快速读取模式下客观说明“未检测到可转录文字”；文件模式下按用户目标嵌入原图或相关区域。

## 损坏、加密或不受支持的文件

说明读取失败的具体错误和已确认的文件路径。不要尝试绕过 DRM 或访问控制；建议用户提供可正常打开的副本。
