# img2md — 图片转Markdown转换器

将图片内容转换为准确、结构清晰的Markdown文档。

## 硬性要求（必须遵守）

### 1. 文字必须一字不差

- **逐字提取**：图片中的每一个字、数字、符号、标点都必须原样输出
- **禁止修改**：不纠正错别字、不改语法、不润色、不简化、不扩展
- **禁止总结**：不要把多段文字合并成一段，不要用自己的话重述
- **禁止推测**：看不清的地方用 `[unclear]` 标记，不要猜测

### 2. 结构必须原样保留

- **标题层级**：图片中的大标题用 `#`，次级标题用 `##`，以此类推
- **列表格式**：有序列表用 `1. 2. 3.`，无序列表用 `-`，保持原图的缩进层级
- **表格格式**：用 Markdown 表格 `| 列1 | 列2 |` 原样复刻，包括表头
- **段落分隔**：图片中的空行、分段必须在输出中体现

### 3. 图表处理规则（严格限制）

**能用 Markdown 表示的，一律用 Markdown 表示，禁止总结：**

| 图片中的图表类型 | 必须使用的 Markdown 格式 |
|-----------------|------------------------|
| 数据表格 | Markdown 表格 `\| 列1 \| 列2 \|` |
| 柱状图/折线图/饼图的数据 | 先提取为数据表格 |
| 流程图 | 用编号列表 `1. 2. 3.` 表示步骤顺序 |
| 组织结构图 | 用嵌套列表表示层级关系 |
| 时间线 | 用表格或列表表示时间点和事件 |
| 包含文字的图片/截图 | 提取所有文字，按原样排版 |

**只有以下内容允许总结（必须标注）：**

- 纯照片（风景、人物、物品照片无文字可提取时）
- 手绘草图、示意图（无文字或文字极少时）
- 复杂的信息图（无法提取为表格的纯视觉元素）

**总结格式（必须加标注）：**
```
> [无法转换为 Markdown 的内容]
> [客观描述图片中的视觉元素，不添加解释或分析]
```

### 4. 禁止的行为

- ❌ 添加任何自己的评论、解释、分析
- ❌ 把图片内容"翻译"成更易懂的说法
- ❌ 合并或拆分段落
- ❌ 改变原文的语序或措辞
- ❌ 省略看似"不重要"的内容（页眉页脚、水印、小字注释都要保留）
- ❌ 对可用 Markdown 表示的内容进行文字描述（必须用 Markdown 格式）

### 5. 不确定内容的处理

- 看不清的文字：`[unclear]`
- 部分可见的文字：`[partially visible: 能看清的部分]`
- 模糊但可能猜到的：`[unclear: 可能是"XXX"]`
- 被遮挡的内容：`[obscured]`

## 工作流程

### Step 1: 读取图片

使用 `Read` 工具查看图片。支持的格式：PNG、JPG、JPEG、GIF、WEBP。

### Step 2: 逐区域提取

按从左到右、从上到下的顺序扫描图片：

1. 页眉/页脚（页码、文档标题、日期）
2. 主标题、副标题
3. 正文段落
4. 列表（有序/无序）
5. 表格
6. 图表/图示 → **判断能否用 Markdown 表示**
7. 注释、脚注、水印

### Step 3: 判断图表处理方式

对于每个图表，问自己：**这个能用 Markdown 表格或列表表示吗？**

- **能** → 转换为表格或列表，**禁止**用文字描述
- **不能** → 用 `> [无法转换为 Markdown 的内容]` 格式进行客观描述

### Step 4: 转换格式

| 图片中的元素 | Markdown 表示 |
|-------------|--------------|
| 一级标题（最大字号） | `# 标题` |
| 二级标题 | `## 标题` |
| 三级标题 | `### 标题` |
| 粗体文字 | `**文字**` |
| 斜体文字 | `*文字*` |
| 无序列表 | `- 项目` |
| 有序列表 | `1. 项目` |
| 表格 | `\| 列1 \| 列2 \|` |
| 代码块 | ` ```语言\n代码\n``` ` |
| 引用/强调框 | `> 内容` |
| 分隔线 | `---` |

### Step 5: 处理特殊内容

#### 手写内容
- 按原样转录，保留错别字和涂改痕迹
- 字迹不清处用 `[unclear]` 标记

#### 数学公式
- 用 LaTeX 格式：`$行内公式$` 或 `$$块级公式$$`
- 不确定的符号：`[unclear symbol]`

#### 多语言内容
- 保留原语言，不翻译
- 除非用户明确要求翻译

#### 多页文档
- 每页之间用 `---` 分隔
- 添加页码标记：`## Page X`

### Step 6: 最终检查

输出前必须确认：

1. [ ] 图片中的每一个可见文字都已提取？
2. [ ] 没有任何内容被简化或改写？
3. [ ] 标题层级、列表、表格格式正确？
4. [ ] 不确定的地方都用 `[unclear]` 等标记？
5. [ ] 没有添加任何自己的评论或解释？
6. [ ] **所有能用 Markdown 表示的内容都已用 Markdown 表示，没有不必要的文字描述？**

## 输出格式

```markdown
# [文档标题或"图片内容"]

[提取的内容，完全按照图片原样，全部用 Markdown 格式表示]

---

> [无法转换为 Markdown 的内容] （仅当图片包含无法表格化/列表化的纯视觉内容时）
> [客观描述图片中的视觉元素]
```

## 示例

### 示例 1：纯文字文档

**图片内容：**
```
会议记录

时间：2024年1月15日
参与人：张三、李四、王五

议程：
1. 上季度总结
2. 下季度计划
3. 预算讨论

备注：下次会议改到周二
```

**正确输出：**
```markdown
# 会议记录

时间：2024年1月15日
参与人：张三、李四、王五

议程：

1. 上季度总结
2. 下季度计划
3. 预算讨论

备注：下次会议改到周二
```

**错误输出：**
```markdown
# 会议记录

本次会议于2024年1月15日召开，由张三、李四、王五参加。
主要讨论了三个议题：上季度工作总结、下季度工作计划以及预算分配问题。
另外，大家商定下次会议改到周二举行。
```
**错误原因**：进行了总结和改写，没有逐字提取。

---

### 示例 2：包含表格的图片

**图片内容：** 一个销售数据表格，列有"产品、Q1销量、Q2销量、Q3销量"

**正确输出：**
```markdown
| 产品 | Q1销量 | Q2销量 | Q3销量 |
|------|--------|--------|--------|
| 产品A | 100 | 150 | 200 |
| 产品B | 80 | 120 | 180 |
```

**错误输出：**
```markdown
图片显示了一个销售数据表格，包含产品A和产品B在三个季度的销量数据。
产品A的销量从Q1的100增长到Q3的200，产品B的销量也有所增长。
```
**错误原因**：用文字描述了表格内容，而没有使用 Markdown 表格格式。

---

### 示例 3：流程图

**图片内容：** 一个三步流程图：开始 → 处理 → 结束

**正确输出：**
```markdown
1. 开始
2. 处理
3. 结束
```

**错误输出：**
```markdown
图片展示了一个简单的流程图，描述了从开始到结束的三个步骤。
```
**错误原因**：流程图可以用有序列表表示，不应该只用文字描述。

---

### 示例 4：纯照片（允许总结的情况）

**图片内容：** 一张风景照片，没有文字

**正确输出：**
```markdown
# 图片内容

> [无法转换为 Markdown 的内容]
> 一张风景照片，显示山脉和湖泊的景色，天空中有云彩。
```

**说明**：这是少数允许使用总结的情况，因为照片没有可提取的文字内容。
