# img2md — 图片转 Markdown 转换器

将图片内容转换为准确、结构清晰的 Markdown 文档。核心原则是**忠实还原**：先逐字提取，再按用户要求保存、合并或总结。

## 触发边界

- 需要 OCR、转录、提取表格/代码/列表、把截图变成 Markdown：使用本技能。
- 用户只要“描述图片里有什么”且图片几乎无文字：可输出客观视觉描述，并标注无法转换为 Markdown 的内容。
- 用户要求编辑、生成或美化图片：不要使用本技能，转向图像生成/编辑能力。
- 多张图片、GIF、多页 TIFF、低质量图片等情况，先读 `references/edge_cases.md`。

## 工作流程

### Step 1: 预处理图片

运行预处理脚本（依赖缺失时会自动安装）：

```bash
python <skill_path>/scripts/prepare_image.py <图片路径> [输出目录]
```

脚本输出 JSON，关注以下字段：
- `needs_split`: 是否进行了裁剪
- `files_to_read`: 待读取的文件路径列表（按此列表顺序读取）
- `split_output_dir`: 长图裁剪片段目录（仅 `needs_split: true` 时存在）

### Step 2: 提取与裁剪内容

按 `files_to_read` 列表逐个用可用的图片读取/视觉工具读取图片。对每个文件按从左到右、从上到下的顺序扫描：主标题 → 正文 → 列表 → 表格 → 图表 → 注释。（页眉、页码、水印等装饰性内容应忽略，详见"可忽略的内容"一节）

**对于语言无法描述的部分（如复杂示意图、手绘草图、照片、包含复杂符号/公式的特定区块等）：**
1. 确定其在图中的位置（坐标）。
2. 在 Markdown 输出文件同级创建 `img/` 目录。
3. 运行裁剪工具提取图片片段：
   ```bash
   python <skill_path>/scripts/extract_utils.py crop <原图/片段路径> <md文件同级目录>/img/<图片文件名>.png <left> <top> <right> <bottom>
   ```
   注：坐标 `<left> <top> <right> <bottom>` 可为绝对像素，也可为归一化坐标 `0.0 - 1.0` 或 `0 - 1000`。
4. 在 Markdown 对应的位置使用相对路径嵌入图片，如：`![描述](img/图片文件名.png)`。

遇到表格、代码、流程图或混合版面时，读取 `references/format_guide.md` 对照格式。

### Step 3: 合并结果（如需要）

如果 `needs_split` 为 `true`，按顺序拼接各片段内容，删除重叠区域的重复内容，确保段落衔接自然。如果裁剪出来的图片引用了分片，需修正 Markdown 中的图片路径。

### Step 4: 输出与整体打包成 ZIP

1. 优先使用图片中的主标题作为 Markdown 文件名（例：`2024年Q1销售报告.md`）。无明确标题时用 3-5 个关键词概括。避免冲突。
2. 确保 Markdown 文件和 `img/` 目录在同一个父目录下。
3. 运行打包工具，将 Markdown 文件与 `img/` 目录整体打包为 ZIP 文件：
   ```bash
   python <skill_path>/scripts/extract_utils.py zip <Markdown路径> [ZIP输出路径]
   ```
4. 输出的最终成果为 ZIP 文件，并明确告知用户 ZIP 文件的实际路径。

## 文字提取原则

这是本 skill 最重要的规则，请务必理解**为什么**：用户给你图片是为了获取其中的文字内容，他们需要的是原始信息的忠实转录，而不是你的解读或改写。

- **逐字提取**：每一个字、数字、符号、标点都必须原样输出
- **禁止修改**：不纠正错别字、不改语法、不润色、不简化、不扩展
- **禁止默认总结**：除非用户明确要求总结，否则不要把多段文字合并成一段
- **禁止推测**：看不清的地方用 `[unclear]` 标记
- **结构保留**：标题层级、列表格式、表格格式、段落分隔都必须在输出中体现

### 可忽略的内容

以下内容属于文档的装饰性/结构性元素，对理解正文内容没有帮助，**应当忽略，不输出**：

- **页码**：如 "第 1 页"、"- 3 -"、"Page 1 of 10"
- **页眉/页脚**：如公司名称、文档模板标题、保密声明（除非用户明确要求保留）
- **水印**：如 "机密"、"DRAFT"、"样本" 等半透明覆盖文字
- **装饰性分隔线**：纯装饰用途的横线、边框图案（但内容性的分隔符如 `---` 应保留）

**判断原则**：如果去掉这个内容不会影响读者对正文的理解，就可以忽略。拿不准时，倾向于保留。

### 不确定内容的处理

| 情况 | 标记方式 |
|------|----------|
| 看不清的文字 | `[unclear]` |
| 部分可见的文字 | `[partially visible: 能看清的部分]` |
| 模糊但可能猜到的 | `[unclear: 可能是"XXX"]` |
| 被遮挡的内容 | `[obscured]` |

### 图表与视觉元素处理规则

| 图片中的元素类型 | 必须使用的 Markdown 格式 |
|-----------------|------------------------|
| 数据表格 | Markdown 表格 `\| 列1 \| 列2 \|` |
| 柱状图/折线图/饼图的数据 | 先提取为数据表格，并在需要时把原图表裁剪为图片保存至 `img/`，在下方以 `![图表描述](img/文件名.png)` 嵌入 |
| 流程图 | 能转录则用编号列表 `1. 2. 3.` 表示步骤；若流程复杂，则裁剪为图片保存至 `img/`，以 `![流程图](img/文件名.png)` 嵌入 |
| 组织结构图 | 能转录则用嵌套列表表示层级；若太复杂，则裁剪为图片保存至 `img/`，以 `![组织结构图](img/文件名.png)` 嵌入 |
| 语言无法描述的视觉内容（照片、手绘草图、示意图、复杂插图、签字等） | **必须裁剪提取为图片**保存至 `img/`，在 Markdown 对应位置以 `![描述](img/文件名.png)` 嵌入 |

**无法用语言描述的内容（如纯照片、手绘草图、示意图、复杂插图等）的图片提取规则：**
1. 严禁只做文字粗略总结。
2. 必须将该元素所在的图片区域裁剪，保存为 PNG 图片，置于 Markdown 同级目录的 `img/` 下。
3. 命好具体文件名，在 Markdown 中使用 `![描述](img/文件名.png)` 嵌入。
4. 若图片有配套文字说明，在图片链接上下文中保留。

## 边界情况处理

多图批量输入、GIF 动图、多页 TIFF、低质量图片等特殊情况的处理方式见 `references/edge_cases.md`。处理前先确认用户是否希望多图合并为一个 Markdown 文件。

## 检查清单

输出前确认：

- [ ] 已运行 `prepare_image.py` 并按 `files_to_read` 读取了所有文件。
- [ ] 每一个可见文字都已提取，没有被简化或改写。
- [ ] 对于语言无法描述的视觉元素（如照片、示意图、复杂图表等），已使用 `extract_utils.py` 裁剪出图片并放入同级 `img/` 目录。
- [ ] Markdown 中已使用 `![描述](img/图片文件名.png)` 格式将提取的图片嵌入到正确位置，确保 md 与 `img/` 文件夹处于同级目录。
- [ ] 标题层级、列表、表格格式正确（详见 `references/format_guide.md`）。
- [ ] 不确定的地方都用 `[unclear]` 等标记，且没有添加任何自己的评论或解释。
- [ ] 已使用 `extract_utils.py` 将 Markdown 文件和 `img/` 目录整体打包为 ZIP 文件，并向用户输出了该 ZIP 文件的路径。
