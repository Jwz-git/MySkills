# img2md — 图片转 Markdown 转换器

将图片内容转换为准确、结构清晰的 Markdown 文档。核心原则是**忠实还原**——逐字提取，不修改、不总结、不推测。

## 工作流程

### Step 1: 预处理图片

运行预处理脚本（依赖缺失时会自动安装）：

```bash
python <skill_path>/scripts/prepare_image.py <图片路径> [输出目录]
```

脚本输出 JSON，关注两个字段：
- `needs_split`: 是否进行了裁剪
- `files_to_read`: 待读取的文件路径列表（**必须按此列表顺序读取**）

### Step 2: 提取内容

按 `files_to_read` 列表逐个用 `Read` 工具读取图片，对每个文件按从左到右、从上到下的顺序扫描：主标题 → 正文 → 列表 → 表格 → 图表 → 注释。（页眉、页码、水印等装饰性内容应忽略，详见"可忽略的内容"一节）

详细的格式对照表和转换示例见 `references/format_guide.md`。

### Step 3: 合并结果（如需要）

如果 `needs_split` 为 `true`，按顺序拼接各片段内容，删除重叠区域的重复内容，确保段落衔接自然。

### Step 4: 输出文件

将 Markdown 文件保存到 `/workspace/` 目录。

**文件命名规则：**
1. 优先使用图片中的主标题（例：`2024年Q1销售报告.md`）
2. 无明确标题时用 3-5 个关键词概括（例：`会议记录_预算讨论.md`）
3. 避免使用 "output"、"result"、"文档" 等无意义名称

## 文字提取原则

这是本 skill 最重要的规则，请务必理解**为什么**：用户给你图片是为了获取其中的文字内容，他们需要的是原始信息的忠实转录，而不是你的解读或改写。

- **逐字提取**：每一个字、数字、符号、标点都必须原样输出
- **禁止修改**：不纠正错别字、不改语法、不润色、不简化、不扩展
- **禁止总结**：不要把多段文字合并成一段
- **禁止推测**：看不清的地方用 `[unclear]` 标记
- **结构保留**：标题层级、列表格式、表格格式、段落分隔都必须在输出中体现

### 可忽略的内容

以下内容属于文档的装饰性/结构性元素，对理解正文内容没有帮助，**应当忽略，不输出**：

- **页码**：如 "第 1 页"、"- 3 -"、"Page 1 of 10"
- **页眉/页脚**：如公司名称、文档模板标题、保密声明（除非用户明确要求保留）
- **水印**：如 "机密"、"DRAFT"、"样本" 等半透明覆盖文字
- **装饰性分隔线**：纯装饰用途的横线、边框图案（但内容性的分隔符如 `---` 应保留）

**判断原则**：如果去掉这个内容不会影响读者对正文的理解，就可以忽略。拿不准时，倾向于保留。

### 不确定内容的处理

| 情况 | 标记方式 |
|------|----------|
| 看不清的文字 | `[unclear]` |
| 部分可见的文字 | `[partially visible: 能看清的部分]` |
| 模糊但可能猜到的 | `[unclear: 可能是"XXX"]` |
| 被遮挡的内容 | `[obscured]` |

### 图表处理规则

| 图片中的图表类型 | 必须使用的 Markdown 格式 |
|-----------------|------------------------|
| 数据表格 | Markdown 表格 `\| 列1 \| 列2 \|` |
| 柱状图/折线图/饼图的数据 | 先提取为数据表格 |
| 流程图 | 用编号列表 `1. 2. 3.` 表示步骤顺序 |
| 组织结构图 | 用嵌套列表表示层级关系 |
| 时间线 | 用表格或列表表示时间点和事件 |

**只有以下内容允许总结（必须标注）：**
- 纯照片（风景、人物、物品照片无文字可提取时）
- 手绘草图、示意图（无文字或文字极少时）
- 复杂的信息图（无法提取为表格的纯视觉元素）

总结格式：
```
> [无法转换为 Markdown 的内容]
> [客观描述图片中的视觉元素]
```

## 边界情况处理

多图批量输入、GIF 动图、多页 TIFF 等特殊情况的处理方式见 `references/edge_cases.md`。

## 检查清单

输出前确认：

- [ ] 已运行 `prepare_image.py` 并按 `files_to_read` 读取了所有文件
- [ ] 每一个可见文字都已提取，没有被简化或改写
- [ ] 标题层级、列表、表格格式正确（详见 `references/format_guide.md`）
- [ ] 不确定的地方都用 `[unclear]` 等标记
- [ ] 没有添加任何自己的评论或解释
- [ ] 输出文件已保存到 `/workspace/`
