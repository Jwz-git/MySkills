# 知识归档决策与写入规范

决定写回知识库后，完整执行本规范。目标不是保存“这次搜到了什么”，而是把可靠、可复用的知识变成现有知识体系的一部分。

## 1. 分开判断内容价值与目标位置

先写一句候选知识的核心命题，再分别回答：

1. **它值得保存吗？** 是否可靠、可复用、非重复、不过度短命。
2. **它属于哪里？** 哪个现有主题能够解释它与其他知识的关系。

不要因为某个实体有名字就为它创建文件。文件表示稳定主题，标题表示主题内的知识点。

## 2. 目标文件选择顺序

按顺序选择第一个合理目标：

1. 已有同义或近义章节；
2. 已有上位主题文件；
3. 已有领域综述或方法文件；
4. 同目录下可扩展的索引/MOC 所指向的主题文件；
5. 新建一个能容纳多个相关知识点的稳定主题文件。

为每个候选目标检查：

- 现有内容是否与新知识共享问题域，而不只是出现相同关键词；
- 读者以后最可能从哪里寻找该知识；
- 写入后是否会造成文件主题漂移；
- 是否存在更具体但仍足够宽的主题。

若两个目标同样合理且选择会显著改变知识库结构，先回答用户，再询问归档位置；不要复制到两个文件制造双源。

## 3. 目录选择

先识别知识库是扁平结构还是分层结构。不要因为一般知识分类常识而覆盖该知识库自己的分类法。

1. 从根目录开始，读取目录索引、README/MOC（如存在）和代表性文件。
2. 为候选目录写出一句职责描述，并用实际文件内容验证，而非只看目录名。
3. 选择职责能覆盖候选知识的最深层现有目录；若更深目录只覆盖某个相邻子主题，则停在上一级。
4. 若知识库一直采用扁平文件结构，继续放在现有层级，不自行引入目录树。
5. 只有一个稳定分类已经有多个文件可归入，或有清晰证据会持续容纳多个文件时，才新建目录。
6. 新目录的语言、大小写、编号和分隔符必须继承同级目录惯例。

不要为单个模型、论文、术语或一次搜索结果创建目录。若必须创建目录，同时检查父级索引是否按惯例需要更新。

## 4. 文件命名粒度

使用“可容纳至少数个同类章节的最小稳定主题”作为新文件名。

| 候选知识 | 不推荐 | 推荐方向 |
| --- | --- | --- |
| BERT 的掩码语言建模 | `BERT.md` | `预训练语言模型.md` 或 `自然语言处理.md` |
| FlashAttention 的 IO 思路 | `FlashAttention.md` | `注意力机制.md` 或现有的 `高效注意力.md` |
| Python 的上下文管理器细节 | `contextmanager.md` | `Python.md` 或 `Python资源管理.md` |
| 某论文的一条实验结论 | 用结论句作文件名 | 论文笔记、研究主题或方法比较文件 |

以下条件全部满足时，实体级文件才可能合理：

- 实体本身是知识库长期维护的一等对象；
- 预期会有多个独立章节，而非一段定义；
- 同目录的分类规则明确采用实体级文件；
- 用户没有要求把该类实体放入更宽主题。

用户明确禁止的原子命名优先于同目录惯例。例如不得因为存在模型单页就创建 `BERT.md`。

## 5. 同目录格式继承

新建文件前列出同目录知识文件，并读取至少两个最相近文件；少于两个则读取全部。建立一个简短的“格式画像”：

- 扩展名与文件名语言、大小写、分隔符；
- 是否有 YAML frontmatter，字段、顺序、日期格式和标签风格；
- 是否以文件名代替一级标题，或是否保留 `# 标题`；
- 常用标题深度和段落顺序；
- 列表、表格、代码块、数学公式的写法；
- 内部链接是标准 Markdown、Wiki link 还是纯路径；
- 引用是脚注、行内链接、参考文献表还是“来源”小节；
- 是否有固定的更新时间、状态、别名或 MOC 字段。

执行规则：

- 主题最相近的同级文件优先于纯粹的多数样式；
- 多个近邻一致时完整复用其骨架；
- 不复制与新主题无关的字段值、标签或占位内容；
- 不为了统一风格而改动现有同级文件；
- 无同级样例时才使用通用 Markdown 格式。

## 6. 合并到现有文件

1. 读取整个目标章节以及前后相邻章节。
2. 搜索新知识的同义词、缩写和旧表述，识别重复或冲突。
3. 将信息放到读者预期的位置：
   - 定义靠近概念介绍；
   - 机制靠近原理；
   - 证据靠近对应结论；
   - 限制靠近适用边界；
   - 来源沿用文件既有格式。
4. 优先改写并合并已有段落；只有真正新增维度时才增加小节。
5. 保留作者原有判断。若新证据修正旧内容，明确标注日期、版本或证据差异，不静默覆盖。
6. 不把检索日志、搜索词、浏览过程写进知识正文。

## 7. 证据与来源

每条持久化的外部关键结论至少对应一个可追溯来源。优先记录：

- 页面或论文标题；
- 作者/机构；
- 正式链接、DOI 或稳定标识；
- 发布日期、版本和必要时的访问日期；
- 能定位主张的章节、表格或页码。

只做必要的短引述，其余使用忠实改写。对推断使用“这意味着”“可能”“在这些条件下”等限定词，不把推断伪装成来源原话。

时效性内容必须注明“截至 YYYY-MM-DD”或版本号。若信息很快失效且知识库没有维护此类历史记录的惯例，不保存。

## 8. 最小改动与验证

写入后逐项检查：

- 新段落是否回答了一个清晰问题；
- 是否与已有段落重复或矛盾；
- 文件主题是否仍然单一；
- 新文件是否真的比新增章节更合理；
- 格式是否能与任一相近同级文件并排而不突兀；
- 链接和引用是否可解析；
- diff 是否只包含本次知识增量。

发现目标选错时，先移动本次新增内容到正确位置，再删除仅由本次任务产生的空壳；不要触碰用户既有文件。
