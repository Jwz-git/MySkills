# 论文分析笔记唯一模板与写作指南

本文件定义 `deep-read` 与 `batch-rewrite` 的唯一输出模板。所有论文类型保持相同的一级/二级标题和顺序；类型差异只体现在内容，不通过改标题表达。

## 1. 写作前准备

先完成以下内部记录，再开始写 Markdown：

1. canonical ID、PDF/官方页面、版本和分析依据。
2. 论文类型：实验方法、理论、综述、Benchmark/数据集、系统/框架、定性/人文社科；可组合。
3. 3–8 条核心主张及原文定位。
4. 关键数字的完整口径：数据集、split、指标、方向、模型/设置和比较对象。
5. 1–3 张候选原图及图号、PDF 页码、用途。
6. 代码、数据、依赖、硬件/成本、许可证和已知缺失项。

证据不足时先降低 `分析依据` 和结论强度，不先写一篇“看起来完整”的笔记再用占位符修补。

## 3. 各部分写作要求

### 3.1 一句话总结

- 用最强但不过界的结论，不把论文摘要中的宣传语直接升级为事实。
- 实验论文通常写“问题 + 方法 + 代表性结果”；理论、综述和定性论文可用定理、分类框架或主要发现替代数字。
- `full-text` 的高亮数字同段写定位；`abstract-only` 只能写摘要明确给出的数字并标 `（Abstract）`。
- “首次”“SOTA”“显著”写清比较范围；无法核验时改为“作者报告”。

### 3.2 基本信息

- `date` 表示本次笔记重写/整理日期；同一批次使用同一日期。
- `发表状态` 区分预印本、已接收、正式会议/期刊；arXiv 不等于 venue。
- `版本或日期` 记录实际阅读版本；PDF 与 arXiv 作者/内容不一致时说明采用哪一版。
- `分析依据` 必须是三个枚举值之一。
- 代码、数据和许可证的动态状态记录核验日期；未访问就写 `未核验`。

### 3.3 研究背景与问题

按“任务是什么 → 为什么重要 → 现有方法怎样做 → 具体哪里不足 → 本文假设为何可能成立”推进。首次出现的缩写、数据集和指标要给出简明定义。背景只写理解本文所需内容，不写泛化教科书。

### 3.4 方法或论证框架

对每个关键组件写清：

1. 输入和输出。
2. 内部机制或论证步骤。
3. 设计动机。
4. 与前后模块的关系。
5. 原文证据或公式定位。

公式的写作顺序是“计算目的 → 符号 → 运算 → 直觉 → 在系统中的作用”。不要依据方法名称补出论文没有描述的训练阶段、损失或实现细节。

### 3.5 证据与结果

- 先说明指标好坏方向和协议；否则数字不可解释。
- 主结果写绝对值与明确对照；百分点和相对百分比不能混用。
- 消融只证明被测试设置中的关联；要声称某组件“导致”提升，需排除额外训练、参数、数据等混杂因素。
- 结果解释分成“作者解释”和“分析判断”。后者说明基于哪条证据。
- 核心证据表通常 3–8 行，覆盖一句话总结与最终总结中的强结论。

### 3.6 合理性与可行性评估

此节不是泛泛优缺点清单。用以下问题检查：

- 任务设定和数据是否代表目标场景？
- 核心假设是否可证伪，论文是否真的测试了它？
- 对照是否公平，指标是否对应用户关心的结果？
- 结果是否跨数据、seed、规模或环境稳定？
- 是否公开代码/权重/数据，许可证和依赖是否清楚？
- 训练、推理、存储、标注和集成成本是否可承受？
- 真实部署最可能在哪些输入或环境下失效？

给出条件化结论，例如：“在作者公开权重、数据可下载且只需推理复现的条件下可直接验证主表；从头训练的 GPU 小时未报告，因此训练复现成本当前无法确认。”

### 3.7 局限、改进与展望

每条局限注明来源：

- `作者明确指出`：论文 limitations/conclusion 明示。
- `基于证据的分析判断`：由数据覆盖、失败案例、未报告资源或比较设置推导。

改进不写“使用更大模型/更多数据”等空泛口号。每个方向给出改什么、用什么对照/指标验证、可能牺牲什么。

### 3.8 图片嵌入与讲解

遵循 `figure-workflow.md`。图片应与讲解放置在一起，内嵌于相应二级标题下（如方法、实验或结果中），并明确支持在 md 中引入多个图片。图解应告诉初学者从哪里开始读，并限定图能证明的结论。结果图解释坐标轴、图例、误差条和好坏方向；架构图解释输入、数据流、训练信号和输出。无可用图时，无需单独段落或标题，可在对应讲解内容中说明原因。

### 3.9 总结

只收束正文已经论证的内容。至少包含贡献、最强证据及范围、可行性/关键局限。总结中的强数字必须在核心证据表出现。

## 4. 类型适配

| 类型 | §2 重点 | §3 重点 | §4 重点 |
|---|---|---|---|
| 实验方法 | 架构、训练、推理、损失 | 主结果、消融、失败案例 | 公平对照、成本、复现 |
| 理论 | 定义、假设、定理、证明思路 | 定理适用条件、数值/经验验证 | 假设强度、证明范围 |
| 综述 | 分类框架、纳入标准、组织方法 | 覆盖范围、趋势、研究空白 | 检索偏差、时效性 |
| Benchmark/数据集 | 构建流程、标注、任务与指标 | 数据统计、基线、诊断结果 | 代表性、泄漏、许可、评测成本 |
| 系统/框架 | 组件、接口、数据流、部署 | 吞吐、时延、扩展性、质量 | 工程依赖、运维和失败恢复 |
| 定性/人文社科 | 研究设计、材料、编码/论证 | 主题、案例、可信度证据 | 抽样、研究者偏差、可迁移性 |

同一论文可以是复合类型，仍使用同一模板。

## 5. 格式与风格

- 默认面向了解一般机器学习但不熟悉该子领域的读者；关键术语首次出现时解释。
- 使用 `==...==` 高亮少量核心术语/数字；`**...**` 用于一般强调，避免整段高亮。
- 表格用于口径明确的对比，不把长段落硬塞进表格。
- Callout 可用 `info`、`note`、`important`、`success`、`warning`、`abstract`；至少保留规定的定位与总结 callout。
- 事实用“论文报告/作者指出/表 X 显示”，分析判断用“基于……，这提示/可能意味着”，建议用“可通过……验证”。
- 不引用无法解析的本地路径，不保留裸模板、省略号、TODO、`[待补充]` 或工具内部 token。
