# 证据、比较与结论强度规范

本文件约束论文笔记“能说什么、应如何定位、何时必须降级”。目标不是堆引用，而是让读者可以从每条重要结论回到原文，并知道结论的适用边界。

## 1. 来源层级与证明对象

不同来源能证明的事情不同，不要把它们笼统称为“主来源”。

| 层级 | 来源 | 主要证明对象 | 不能单独证明 |
|---|---|---|---|
| A | 论文正文、附录、补充材料 | 方法、公式、实验、作者结论、声明的局限 | 当前代码状态、论文外泛化 |
| B | DOI/出版社/会议页、OpenReview、ACL Anthology、arXiv 官方页 | 身份、作者、版本、发表状态、正式材料入口 | 论文未写的实现细节 |
| C | 作者官方代码、项目页、数据页 | 代码/权重/数据/许可证/运行说明的当前状态 | 论文实验结果之外的普遍有效性 |
| D | 第三方复现、综述、博客、媒体 | 线索、外部经验、争议和复现补充 | 原论文事实或官方状态 |

规则：

1. 方法和结果以 A 为核心；身份与版本用 B 交叉核对。
2. 代码/数据可用性属于动态事实，使用 C 并记录 `核验于 YYYY-MM-DD`。
3. D 必须标为外部来源，不能悄悄混入作者结论。
4. PDF 与官方页面版本不一致时，明确本文分析哪一版；页码定位以实际阅读 PDF 为准。

## 2. 分析依据的结论上限

### `full-text`

可以分析完整机制、公式、实验、消融和局限，但仍需原文定位与公平性检查。全文可得不等于所有主张自动可信。

### `partial`

开头说明已获材料范围。只写片段覆盖的内容；未出现的设置写 `当前材料无法确认`。不要用常见领域做法补足论文特定实现。

### `abstract-only`

允许：

- 任务定位。
- 摘要明确描述的方法概念。
- 摘要明确报告的结果，并标 `（Abstract）`。
- 需要全文核验的问题清单。

不允许：

- 具体模块内部机制、损失、训练阶段或超参数。
- 消融、失败案例、精确复现成本。
- 把合理猜测写成作者设计。
- 声称已完成“深度全文分析”。

## 3. 内部证据账本

在写正文前，至少记录下列字段。账本可放临时目录，不必原样交付。

| 字段 | 含义 |
|---|---|
| `claim` | 准备在笔记中表达的主张 |
| `kind` | `paper-fact` / `analysis-inference` / `recommendation` |
| `source` | PDF/附录/官方页/代码仓库 |
| `locator` | 页码 + section/table/figure/equation |
| `setting` | 数据、split、指标、模型配置 |
| `boundary` | 证据没有覆盖的范围 |
| `used_in` | 一句话总结/方法/证据表/总结等 |

一句话总结和最终总结中的每条强主张都应出现在账本里。

## 4. 原文定位格式

采用简短、稳定、可读的括号定位：

```text
（原文 p. 7, Table 2）
（原文 pp. 5–6, §3.2）
（原文 p. 4, Eq. 3）
（原文 p. 9, Figure 5；Appendix §B）
（Abstract）
```

要求：

- 页码指实际阅读 PDF 的页序；若同时写论文印刷页码，注明二者差异。
- 表、图、公式优先同时写页码，便于 PDF 版本变化时寻找。
- 一个段落有多个不同来源的数字时分别定位，不能在段末放一个含糊引用覆盖全部。
- 外部动态事实使用链接并写核验日期，例如“官方仓库提供权重（核验于 2026-07-11）”。

## 5. 事实、分析判断和建议

### 论文事实

使用：`论文报告`、`Table 2 显示`、`作者在 §5 指出`。内容不得超过来源实际表达。

### 分析判断

使用：`基于……的结果，这提示`、`一种可能解释是`、`在……假设下可以理解为`。必须指出推断依据，并明确不是作者已验证的因果结论。

### 建议

使用：`可通过……验证`、`若目标是……，可考虑`。建议要包含实验或工程验证方式与权衡。

禁止使用 `[推断: ...]` 作为免责标签后继续补造细节。标签不能把无证据内容变成可靠分析。

## 6. 数字口径

任何作为结论依据的数值，都检查以下六项：

1. 数据集/材料。
2. split 或评估子集。
3. 指标名称与好坏方向。
4. 模型/骨干/输入设置。
5. 比较对象。
6. 原文定位。

### 绝对变化与相对变化

从 30% 到 39%：

- 绝对变化：`+9 个百分点`。
- 相对变化：`(39-30)/30 = 30%`，写 `相对提升 30%`。

除非论文明确给出口径，否则不要只写“提升 9%”。重新计算的值标为“据表中数值计算”，并保留足够精度，避免把四舍五入误差说成精确结论。

### 平均值与汇总指标

- 只有知道组成项和权重时才自行复算平均。
- 表格展示的部分列无法得到论文的 `Average` 时，说明平均可能覆盖未展示任务并回查表头/脚注；不能断言论文算错，也不能把部分列算术平均冒充原指标。
- 上界/下界、渐近复杂度和经验拟合值保持数学语义；`O(f(n))` 不是等式。

## 7. 强结论规则

以下词语需要更高证明门槛：`SOTA`、`最佳`、`最高`、`首次`、`显著`、`证明`、`导致`、`泛化到`、`鲁棒`、`可扩展`、`零额外成本`。

使用前检查：

- 原文是否明确报告，还是笔记作者自行概括？
- 比较集合、论文版本和时间范围是什么？
- 指标、数据、模型规模和预算是否可比？
- “显著”是否有统计检验，还是仅数值更高？
- “首次”是否经过文献检索，还是作者自称？
- “导致”是否有消融/控制实验排除混杂？

安全写法示例：

- `作者报告该设置在其比较表中取得最高 Recall@1；比较限于 Table 2 所列模型，并不等于所有后续方法中的当前 SOTA（原文 p. 7, Table 2）。`
- `移除模块后分数下降，支持该模块与性能相关；由于同时改变了参数量，这一消融不能完全隔离机制本身的因果贡献。`

## 8. 比较公平性

至少核对：

| 维度 | 常见混杂 |
|---|---|
| 数据 | 训练数据数量、数据清洗、额外数据、泄漏 |
| split | validation/test、zero-shot/finetuned、IND/OOD |
| 模型 | backbone、参数量、上下文长度、预训练版本 |
| 输入 | 图像分辨率、crop 数、点数、文本长度 |
| 优化 | epoch/step、batch、负样本、超参搜索预算 |
| 推理 | reranking、test-time augmentation、候选池大小 |
| 成本 | GPU 数/型号、时延、存储、索引构建时间 |

如果关键维度不可比：

1. 仍可准确报告论文表格。
2. 将结论限制为“完整系统在该协议下更高”。
3. 不把差异归因于某一模块，除非有受控消融。

## 9. 合理性检查

用“问题—假设—设计—证据”链审视论文：

- **问题**：成功标准是否对应真实需求？数据是否代理了真正目标？
- **假设**：例如低秩、局部性、共享语义空间或独立同分布假设是否明确？在哪些场景会破坏？
- **设计**：模块是否直接作用于所声称困难，还是只增加容量/数据/计算？
- **证据**：实验或理论是否能区分核心机制与替代解释？

结论分级：

- `充分支持`：多个相互补充的证据直接对应主张。
- `部分支持`：方向一致，但存在覆盖或混杂限制。
- `证据不足`：主张超出实验、理论或材料。

分级必须附理由，不把它变成主观分数。

## 10. 复现与落地可行性

### 复现信息

- 官方代码、commit/release、预训练权重。
- 数据来源、预处理、许可和可获得性。
- 环境、关键依赖、随机 seed、超参数。
- 训练硬件、GPU 小时、显存或作者给出的成本。
- 评估脚本和 checkpoint。

建议使用条件化等级：

- `可直接验证主要结果`：官方权重、数据和评估脚本可得。
- `可部分复现`：核心材料可得，但训练/预处理/许可有缺口。
- `仅能概念验证`：只有论文描述或关键资源缺失。

### 落地信息

- 端到端时延而非单模块时延。
- 峰值显存、常驻内存、索引/权重存储。
- 输入规模扩大时的复杂度和吞吐。
- 线上数据获取、隐私、安全、维护和监控。
- 分布外、噪声、缺模态、错误输入等失败模式。

论文未报告时写 `未报告`，可指出需要怎样测量，但不要发明 GPU 型号、小时或成本。

## 11. 局限与改进链

每条改进建议写成：

1. **观察到的限制**：来自作者声明或明确证据。
2. **影响**：限制会伤害哪个场景/指标/假设。
3. **可执行改动**：具体改模型、数据、损失、评估或系统哪部分。
4. **验证**：对照、数据、指标和失败判据。
5. **权衡**：精度、成本、复杂度、解释性或风险。

示例：

> 论文只在单一城市数据上评估（原文 p. 8, §4.1），因此跨城市泛化证据不足。可保持模型与训练预算不变，在未见城市做 zero-shot 测试，并同时报告 Recall@k 与地理距离误差；这会增加数据准备成本，但能区分方法增益与场景记忆。

## 12. 最终证据审计

逐篇人工核对：

- 一句话总结中的方法、数字和强结论。
- 核心证据表每一行的原文页码/表/图/公式。
- 所有 `==数字==`、SOTA/首次/因果/泛化/局限声明。
- 公式不等式、维度条件、复杂度上界和指标方向。
- PDF 版本、作者、canonical ID、官方链接。
- 图像是否来自对应论文、图号页码是否正确。
- 结论是否明确限制在证据覆盖范围内。
