# Paper Research

## 1. 先选择工作模式

先判断用户真正需要的产物，避免把简单整理扩大成不必要的重研究流程。

| 模式 | 适用请求 | 默认产物 |
|---|---|---|
| `discover` | 找论文、筛选方向、追踪近期工作 | 候选清单、筛选依据、来源链接 |
| `deep-read` | 解读一篇 PDF/arXiv/DOI/标题 | 一篇证据可追溯的标准分析笔记 |
| `batch-rewrite` | 重写一个目录中的多篇论文笔记 | 同一模板的逐篇笔记、资源目录、校验报告 |
| `tidy-only` | 只整理 frontmatter、标签、链接或标题 | 保留正文语义的格式修订 |
| `synthesis` | 比较多篇、写综述、建立研究脉络 | 综合分析；需要时同时保留逐篇笔记 |

用户同时要求多项任务时组合模式。本次请求明确说“重写”时使用 `batch-rewrite`，不能用 `tidy-only` 的“保留正文”规则替代真正重写。

## 2. 按任务读取参考文件

- `deep-read`、`batch-rewrite`、`synthesis`：完整读取 `references/analysis-guide.md` 与 `references/evidence-policy.md`。
- 需要从 PDF 取图：完整读取 `references/figure-workflow.md`。
- `batch-rewrite` 或 `tidy-only`：完整读取 `references/tidy-operations.md`。

精确模板只在 `analysis-guide.md` 定义；其他文件不得复制出不同版本的模板。

## 3. 证据闸门

### 3.1 先确认论文身份

在分析前建立最小来源记录：完整标题、作者、canonical ID（优先 DOI；否则 arXiv ID 与版本）、本地 PDF、官方网络页、PDF 版本/日期、代码与数据来源。标题或简称有多个候选时先核对 PDF 首页、官方页面和 ID；不能凭文件名猜论文。

### 3.2 标记分析依据

每篇笔记必须在基本信息表写一个枚举值：

- `full-text`：已读取正文，并按需检查附录、表格、公式和原图。
- `partial`：只有明确的正文片段或部分页；只分析材料覆盖的内容。
- `abstract-only`：只有摘要；只能给出初步定位、摘要明确声称的贡献和待验证问题。

材料不足时降低结论强度，不用篇幅补偿证据缺口。`abstract-only` 不得补写实现细节、消融、精确资源需求或作者未声明的局限。

### 3.3 使用固定缺失语义

不要使用含义模糊的 `[待补充]`。按实际状态写：

- `未报告`：已检查当前版本，论文没有提供。
- `当前材料无法确认`：材料范围不足。
- `未核验`：可能需外部来源，但本次没有核验。
- `不适用`：该论文类型不需要该字段。

## 4. 来源与检索原则

1. 论文方法、实验和作者结论优先读取论文全文、附录与补充材料。
2. 标题、版本、发表状态优先 DOI、出版社/会议页面、OpenReview、ACL Anthology 或 arXiv 官方页。
3. 代码、数据、许可证和安装方式优先作者官方仓库/项目页；第三方复现只能作为补充。
4. 搜索结果、博客和二手综述可以提供线索，不能独立证明论文事实。
5. `latest`、`recent`、引用量、代码可用性和发表状态具有时间敏感性，必须联网并记录核验日期。
6. 一般主题检索同时覆盖奠基工作和近期代表作；只有用户明确要“最新”时才把时间作为主要筛选条件。

可用时优先使用 `arxiv-search`；不可用时搜索 arXiv、publisher、OpenReview、ACL Anthology 等主来源。获取候选后按主题匹配、证据可得性、发表状态、方法差异和用户用途筛选，不用“疑似顶会”或未核验引用量充当质量证据。

## 5. 通用执行流程

### 5.1 `discover`

1. 从用户用途推导主题、时间、论文类型、数量和排除条件；只有缺失项会改变范围时才提问。
2. 设计互补检索式，合并去重，并核对 canonical ID。
3. 每篇候选用“问题—方法—证据范围—与需求的关系”做短梗概。
4. 用户未指定论文时，请其选择；若授权自动选择，说明排序依据并继续。

### 5.2 `deep-read`

1. 完成身份与分析依据闸门。
2. 提取带页码的正文，建立内部证据表：主张、原文定位、适用边界、事实/分析判断。
3. 识别论文类型；不确定时写“当前材料无法确认”，不默认实验类。
4. 检查问题—假设—设计—证据是否闭环，检查基线公平性和可复现资源。
5. 按 `analysis-guide.md` 写作；按 `figure-workflow.md` 提取并解读关键原图。
6. 运行证据审计与自动校验，修复后再交付。

### 5.3 `batch-rewrite`

按 `tidy-operations.md` 的事务流程执行：

1. `inventory`：列出全部输入、PDF/官方链接、canonical ID、当前状态和预期输出。
2. `snapshot`：在本次运行的临时目录保存可恢复副本与校验和。
3. `extract`：逐篇建立证据表和图像清单；单篇失败不能污染其他文件。
4. `stage`：按同一模板重写，保留用户明确要求保留的文件名和相关链接。
5. `validate`：逐篇做自动检查和原文证据抽查；错误文件不得冒充成功。
6. `replace`：只替换通过验收的目标；报告失败项和原因。
7. `report`：汇总 `discovered / mapped / rewritten / unchanged / failed / errors / warnings`。

### 5.4 `tidy-only`

只修改约定的 frontmatter、标签、链接和层级；不重写用户观点。先读后改、路径按文件实际位置计算、修改后运行校验。若正文与来源明显冲突，报告而不是顺手改写，除非用户同时授权内容修订。

### 5.5 `synthesis`

先保证每篇来源身份与指标口径正确，再按问题设定、关键假设、方法机制、数据/指标、资源成本、适用边界比较。不同 backbone、数据、分辨率、预训练或预算下的数字不能直接推出方法优劣；不可比时明确说明。

## 6. 统一笔记契约

所有 `deep-read` 与 `batch-rewrite` 输出遵循 `analysis-guide.md` 的唯一模板：

1. frontmatter 固定字段顺序：`title`、`date`、`tags`、`aliases`。
2. frontmatter 后首个非空块是 `**原文**:`；本地链接必须从当前 Markdown 位置真实可解析。
3. 四个一级标题固定且各出现一次：
   - `# 一句话总结`
   - `# 论文基本信息`
   - `# 核心内容详解`
   - `# 总结`
4. `核心内容详解` 固定五个二级标题：
   - `## 1. 研究背景与问题`
   - `## 2. 方法或论证框架`
   - `## 3. 证据与结果`
   - `## 4. 合理性与可行性评估`
   - `## 5. 局限、改进与展望`
5. `## 3` 必须包含“核心证据表”：`结论 | 证据 | 原文定位 | 适用边界`。
6. 至少使用一次 `> [!info] 论文定位` 和一次 `> [!abstract] 论文总结`。
7. 不添加额外一级标题；图片与讲解放置在一起并支持引入多个图片，延伸阅读、相关笔记或补充链接放在对应小节内。

理论、综述、Benchmark、系统和定性论文保持同一标题结构，只调整段落内容；不存在的训练、基线或数据字段写 `不适用`，不能硬套实验类叙事。

## 7. 合理性、可行性与改进要求

分析不能停留在“方法很新、结果很好”。至少回答：

- **问题合理性**：任务设定是否对应真实需求，关键假设在哪些场景成立？
- **设计合理性**：每个核心组件解决哪条困难；消融或理论是否支持其必要性？
- **证据充分性**：数据、指标、对照、统计和失败案例能支持多强的结论？
- **比较公平性**：数据、split、backbone/规模、预训练、输入、训练预算和推理设置是否可比？
- **复现可行性**：代码、数据、依赖、硬件、训练/推理成本、随机性和许可证是否报告？
- **落地可行性**：时延、内存/存储、扩展性、数据获取、隐私/安全和失败模式有什么约束？

每条改进建议使用“观察到的限制 → 为什么重要 → 可执行改动 → 验证实验 → 预期代价/权衡”的链条。没有证据的方向只能写作分析建议，不能伪装成作者结论。

## 8. 数字与强结论纪律

- 数字同时写清数据集、split、指标、好坏方向和设置，并紧邻原文定位，如 `（原文 p. 7, Table 2）`。
- “提升 9%”必须说明是 `+9 个百分点` 还是 `相对提升 9%`。
- `SOTA`、`最高`、`首次`、因果解释和泛化结论只在原文证据与比较范围支持时使用；写明范围与论文版本日期。
- 一张表格中的相关性或单个消融结果不能自动证明因果；将可能解释写成“基于……的分析判断”。
- 总结中的每个高亮数字都应能回溯到正文证据表。

完整规则见 `evidence-policy.md`。

## 9. PDF、图片与临时文件

- 优先使用已有运行时和虚拟环境；缺少可选依赖时采用文本提取、页面渲染等降级方案，不隐式污染全局环境。
- 文本提取保留页码标记；多栏、扫描、公式和表格需回看渲染页，不能只信抽取顺序。
- 全文深读通常保留 1–3 张最能解释方法或证据的原图；图片应与讲解放置在一起，内嵌于相应二级标题下（如方法、实验或结果中），并明确支持在 md 中引入多个图片。图片少而有用优于批量堆图。
- 有原论文图时不使用 Mermaid 重画；无可用图时，使用`mermaid`绘制说明图。
- 临时文件统一放在本次运行目录（如 `/tmp/paper-research/<run-id>/`）；只清理 manifest 明确属于本次运行的文件。

## 10. 路径与归档

推荐目录：

```text
论文/
├── 论文原件/
├── AI分析/
└── images/
    └── <note-stem>/
```

- 笔记、PDF、图片的映射记录在 inventory/manifest 中，不仅依赖同名 stem。
- 批量重写默认保留现有文件名；新建时用简短标题，发生碰撞则追加 canonical ID。
- 从 `AI分析/<name>.md` 指向同级目录的 PDF 通常是 `../论文原件/<file>.pdf`，图片通常是 `../images/<note-stem>/<file>.png`。始终按实际路径计算并验证。
- 标签使用唯一的 `paper/<lower-kebab-case>`，通常 2–5 个；aliases 去重。

## 11. 验收

自动检查使用：

```bash
python3 scripts/validate_notes.py /path/to/论文/AI分析 --strict
```

无 `rg` 的环境直接使用脚本；脚本依赖标准库和 `pathlib`。自动校验只能检查结构、路径和部分证据形态，不能证明事实真实性，因此还要逐篇抽查：一句话总结、核心证据表、所有高亮数字、SOTA/首次/因果/局限声明及图号页码。

交付前确认：

- 所有目标文件进入明确终态，没有漏项或静默失败。
- 全部文件模板和标题顺序一致，无 Mermaid、`[待补充]`、TODO 或模板占位符。
- 本地 PDF/图片链接存在，图像可读，图号与页码匹配。
- 关键数字与强结论有定位，事实、分析判断和建议边界清楚。
- 合理性、比较公平性、复现与落地可行性得到实质评价。
