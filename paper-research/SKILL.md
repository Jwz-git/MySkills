# 论文完整工作流 Skill

## 1. 技能概览

### 1.1 能力矩阵

本技能整合三大核心能力，形成从检索到归档的完整闭环：

| 能力 | 说明 |
|------|------|
| **论文检索与研究** | 需求确认→arXiv检索→初筛→下载→文本提取 |
| **深度结构化分析** | 五段式报告：一句话总结→基本信息→核心详解（四小节）→流程图→总结 |
| **笔记格式标准化** | Frontmatter/Tags/Links整理、文档结构标准化、批量编辑 |

### 1.2 工具链

| 工具 | 用途 |
|------|------|
| `arxiv搜索` skill | 学术论文检索与下载 |
| `WebFetch` | 获取论文元数据、兜底搜索 |
| `curl` | PDF 下载兜底：`curl -L -o "path/file.pdf" "https://arxiv.org/pdf/XXXX.XXXXX"` |
| `pdfplumber` (Python) | PDF 文本提取 |
| `tavily-search-mcp` | 搜索论文 arXiv 编号（补充） |
| `Read` / `Edit` / `Write` | 文件读取与编辑 |
| `Glob` / `grep` | 文件查找与校验 |

### 1.3 工作目录

```
知识库根目录/
├── 论文/
│   ├── 论文原件/        # 存放 PDF 原文
│   ├── AI分析/          # 存放论文笔记
│   └── images/          # 论文相关图片
```

用户目录结构不同时，先确认对应关系再执行。

### 1.4 工作流总览

```mermaid
flowchart TB
    A["需求确认<br/>主题/过滤条件"] --> B["论文检索<br/>arXiv搜索"]
    B --> C{"用户确认<br/>选择论文"}
    C --> D["PDF下载<br/>+文本提取"]
    D --> E["深度分析报告<br/>五段式结构"]
    E --> F["格式标准化<br/>Frontmatter/Tags"]
    F --> G["归档+汇总"]
```

### 1.5 核心原则

- **流程必用 Mermaid** — 所有涉及流程、架构、结构、工作流的内容（包括本 skill 覆盖的分析报告和格式整理流程），都必须使用 Mermaid 可视化呈现，不能仅用纯文本描述
- **真实可信** — 关键结论必须真实且符合原文，避免凭空补全与臆造
- **宁深勿浅** — 每个技术点必须讲透

## 2. 第一阶段：需求确认与检索规划

与用户确认以下信息后制定检索策略。**若关键信息缺失，必须先提问再检索**：

1. **研究主题与关键词** — 核心关注什么？是否有已知的重要论文作为起点？
2. **过滤条件**：
   - 年份范围（如 2023-2025）
   - 论文类型（实验类/综述类/理论类）
   - arXiv 分类（如 cs.CV 计算机视觉、cs.LG 机器学习、cs.CL 计算语言学等）
   - 会议来源偏好（如 CVPR, NeurIPS, ICML, ACL）
3. **数量目标** — 期望分析多少篇？（推荐 3-5 篇可深入分析）
4. **特殊要求** — 排除/侧重特定子方向、只关注有开源代码的论文等
5. **用途与侧重点** — 综述/落地/复现？更看重方法创新还是实验指标？

> 如果用户一次性信息足够充分，可直接进入检索，无需重复确认。

---

## 3. 第二阶段：论文检索与筛选

### 3.1 构建检索 Query

设计 1-2 组检索式，覆盖不同角度：
- 精确短语用引号包裹：`"visual place recognition"`、`"low-rank adaptation"`
- 组合概念：`"vision language model" AND "localization"`
- 排除噪音：`"LoRA" ANDNOT "survey"`
- 设置 arXiv 分类过滤，提升结果精准度

### 3.2 执行检索

使用 `arxiv搜索` skill 进行检索：
- `max_results: 15-20` — 获取足够候选
- `sort_by: "relevance"` — 默认按相关性排序；调研最新进展时用 `"date"`
- `categories` — 设置分类过滤

> 兜底：若 `arxiv搜索` skill 不可用，使用 `WebFetch` 直接访问 `https://arxiv.org/search/?query=...`。

### 3.3 初筛与排序

- 检查标题与用户主题的匹配度
- 获取摘要（`get_abstract`）评估内容相关性
- 评估来源（arXiv 本身、疑似顶会投稿）
- 多组检索结果合并去重

### 3.4 逐篇梗概

为每篇候选生成清晰梗概，**用于用户选择**。推荐格式：
- 100-150 字摘要 + 3-5 条要点
- 覆盖：研究问题、方法思路、核心结果/贡献、适用场景/局限（若摘要可推断）

**必须请用户选择后再进入下一步。** 未选择前不要下载或分析。

## 4. 第三阶段：论文下载与文本提取

### 4.1 下载 PDF

使用 `arxiv搜索` skill 下载 PDF。
> 兜底方案：`curl -L -o "论文/论文原件/文件名.pdf" "https://arxiv.org/pdf/XXXX.XXXXX"`

PDF 文件名使用基于标题的简短命名：提取论文标题中的核心关键词，用连字符连接，简洁直观。例如：`MLP-Memory.pdf`、`VLM-Loc.pdf`、`DC-VLAQ.pdf`

### 4.2 提取正文文本

使用 Python 的 `pdfplumber` 库提取 PDF 文本内容：

```python
import pdfplumber
with pdfplumber.open(pdf_path) as pdf:
    for page in pdf.pages:
        text = page.extract_text()
```

> `Read` 工具读取 PDF 可能失败（显示"Unsupported Document"），此时必须用 `pdfplumber` 兜底。先检查系统是否有该库（`python3 -c "import pdfplumber"`），如无则 `pip install pdfplumber`。

### 4.3 获取元数据

使用 `WebFetch` 访问 `https://arxiv.org/abs/XXXX.XXXXX` 获取标题、作者、摘要等元数据。

### 4.4 保存 PDF

- 将 PDF 保存到 `论文/论文原件/` 目录
- 文件名使用基于标题的简短命名（如 `MLP-Memory.pdf`、`VLM-Loc.pdf`），提取核心关键词，简洁直观

## 5. 第四阶段：深度结构化分析报告生成（核心）

**这是本技能最核心的环节。** 对每篇论文生成五段式深度分析报告。**要求：讲解必须详尽，宁深勿浅，每个技术点都要讲透。**

### 5.1 输入获取

根据输入类型选择获取方式，优先拿到完整正文：

| 输入类型 | 获取方式 |
|----------|---------|
| PDF 文件 | 直接读取；失败则用 `pdfplumber` 兜底 |
| DOI / arXiv ID | 访问 `https://arxiv.org/abs/{ID}` 获取全文 |
| 论文链接 | 支持 arXiv、ACL Anthology、OpenReview、Semantic Scholar 等。遇付费限制则说明并请用户提供 PDF |
| 论文标题 | 用搜索工具查找并确认匹配；多个候选时请用户确认 |
| 论文片段（摘要/段落） | 基于现有片段分析，标注"[基于部分内容分析]"，建议用户提供完整论文 |

### 5.2 论文类型识别

先判断论文类型以决定分析侧重点。判断依据为标题、摘要和引言前几段；无法确认时按实验类保守处理并说明。

| 论文类型 | 特征 | 分析侧重点 |
|----------|------|-----------|
| **实验类** | 提出新模型/方法，有定量实验 | 方法架构、实验结果、消融实验 |
| **理论类** | 以数学证明/定理为主 | 理论框架、证明思路、理论意义 |
| **综述类** | 系统梳理某一领域 | 分类体系、发展趋势、研究空白 |
| **系统/框架类** | 提出软件系统或工程框架 | 系统架构、设计决策、性能基准 |
| **人文社科类** | 定性研究为主 | 研究方法、论证逻辑、社会意义 |

### 5.3 五段式输出结构

> 完整的格式模板、写作指南和示例见 `references/analysis-guide.md`。

按以下五段结构生成报告：

#### 5.3.1 一句话总结

1-2 句概括核心贡献，`==高亮==` 关键术语和核心数字。包含：核心问题 + 提出方法 + 关键结果。

#### 5.3.2 论文基本信息

表格呈现元数据（标题/作者/机构/arXiv ID/日期/类型/方法/基线/代码/数据集），附 `> [!info] 论文定位` callout。信息不完整时标注 `[待补充]`，不要臆造。

#### 5.3.3 核心内容详解（四小节）

报告主体，**必须详尽展开**。根据论文类型调整侧重（见 §5.2），保持四小节结构：

| 小节 | 目标 |
|------|------|
| ① 研究背景与问题 | 为什么重要、现有方法为什么不够好 |
| ② 方法方案 | 方法如何工作、每步设计动机 |
| ③ 实验效果 | 实验证明了什么、结果有多好、为什么好 |
| ④ 改进空间与展望 | 客观评价局限与合理改进方向 |

每个小节的必须涵盖项和详细要求见 `references/analysis-guide.md` §1.3。

#### 5.3.4 流程图详解

**必须提供 Mermaid 流程图**（信息严重不足时除外）。每个流程图必须附逐步说明。

| 论文类型 | 流程图类型 |
|----------|-----------|
| 实验类（有训练） | 训练流程图 + 推理/架构图 |
| 实验类（无训练） | 输入→处理→输出图 |
| 理论类 | 证明思路图／推导脉络图 |
| 综述类 | 分类体系图／时间线演进图 |
| 系统类 | 系统架构图／模块交互图 |

Mermaid 模板、节点换行规则（用 `<br/>` 非 `\n`）和降级原则见 `references/analysis-guide.md` §1.4。

#### 5.3.5 总结

使用 `> [!abstract] 论文总结` callout 收束全文，突出最重要的贡献和数据。

### 5.4 写作原则与讲解策略

> 写作原则、Callout 规范和五项增强讲解策略的完整说明见 `references/analysis-guide.md` §2-4。

**核心要求：**
- **宁深勿浅** — 每个技术点回答"为什么"和"怎么做"，先核心思想→架构→细节
- **流程必用 Mermaid** — 所有涉及流程、架构、结构的内容必须可视化
- **事实优先** — 区分事实（"作者指出"）与推论（"可能暗示"），不要臆造
- **语言跟随用户** — 专业术语保留原文并附注释；`==高亮==` 关键术语和数字

### 5.5 检查清单

**基础检查：**
- [ ] 输入类型识别正确；多个候选论文已确认
- [ ] 论文类型判断明确
- [ ] 五段式结构完整：一句话总结→基本信息→核心详解→流程图→总结
- [ ] 核心详解四小节顺序正确（背景→方法→实验→展望）
- [ ] 关键结论客观真实，合理推断在语言表述上已清晰区分
- [ ] `==高亮==` 标记关键术语和核心数字
- [ ] Callout 使用规范
- [ ] 流程图存在且与正文一致；信息不足时已降级说明
- [ ] 所有流程/架构/结构内容已用 Mermaid 可视化，而非纯文本

**详细检查：**
- [ ] 方法部分每个关键组件解释了"为什么这样设计"
- [ ] 对比分析使用了结构化方式（表格/并列说明）
- [ ] 关键公式有符号解释和自然语言翻译
- [ ] 实验结果有深层解读（不只是数字，还有分析和洞察）
- [ ] 局限性有依据（论文提及或合理推断）
- [ ] 背景概念对不熟悉者做了解释
- [ ] 未臆造实验数值、数据集或方法细节

## 6. 第五阶段：格式标准化与归档

对分析笔记进行元数据和格式标准化。详细操作模式（四种模式、标签映射、校验方式）见 `references/tidy-operations.md`。

### 6.1 标准格式框架

**Frontmatter：**

```yaml
---
title: "论文完整标题"
date: YYYY-MM-DD
tags:
  - paper/主题1
  - paper/主题2
aliases:
  - 简称1
  - 简称2
---
```

- `tags` 必须使用 `paper/xxx` 层级格式（如 `paper/vlm`、`paper/lora`）
- `aliases` 包含论文简称和其他常用提法
- `date` 为整理/创建日期

**正文结构：**

第一行在 frontmatter 之后：
```markdown
**原文**: [本地](论文/论文原件/文件名.pdf) [网络](https://arxiv.org/abs/XXXX.XXXXX)
```

然后按五段式结构组织正文。

### 6.2 核心原则

- **先读后改** — 修改前先读取所有受影响文件的 frontmatter 和结构
- **先规划后执行** — 编辑前说明变更计划；用户提供明确映射表则跳过确认直接执行
- **并行编辑** — 所有编辑相互独立，一次性批提交
- **编辑后校验** — 使用 `grep` 确认旧值已清除、新值已出现

### 6.3 工作流程

```mermaid
flowchart TB
    A["① 理解目标<br/>范围/PDF/结构"] --> B["② 发现与读取<br/>Glob查找+Frontmatter"]
    B --> C["③ 规划变更<br/>旧→新映射表"]
    C --> D["④ 执行编辑<br/>Edit并行批处理"]
    D --> E["⑤ 校验<br/>grep确认新旧值"]
    E --> F["⑥ 汇总报告<br/>变更统计表"]
```

**步骤 1：理解目标状态** — 澄清范围（哪些文件/目录）、是否涉及 PDF 链接、是否需要标准化文档结构、是否需要补全论文基本信息表。

**步骤 2：发现并读取** — 使用 `Glob` 查找 MD 文件，并行读取 frontmatter（前 10-15 行），记录无 frontmatter 的文件，建立 MD ↔ PDF 映射表。

**映射规则：** `AI分析/` 目录下的 `.md` 文件 → `论文原件/同名.pdf`。文件名使用基于标题的简短命名（如 `MLP-Memory.md` ↔ `MLP-Memory.pdf`），简洁直观。

**步骤 3：规划变更** — 为每个文件构建旧→新映射，输出变更摘要（受影响文件数、标签映射、补充的 section 结构）。

**步骤 4：执行** — 使用 `Edit`（`replace_all: false`）并行成批编辑所有文件。

**步骤 5：校验** — 两次 grep 校验：旧值已消失、新值已出现。报告每个检查的通过/失败。

**步骤 6：汇总报告** — 输出变更统计表（目录/文件数/变更类型/状态）。

### 6.4 操作模式与注意事项

四种常见操作模式（A-添加原文 PDF 链接 / B-标签层级重构 / C-标准化文档结构 / D-清理冗余属性）的详细说明、标签映射表、校验方式和注意事项见 `references/tidy-operations.md`。

**精选论文**: 共 N 篇

| # | 论文 | arXiv ID | 类型 | 方向 |
|---|------|----------|------|------|
| 1 | ... | ... | ... | ... |

多篇论文时追加：
- 各论文核心方法对比

## 8. 边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 检索结果太少（<3） | 放宽关键词或分类，扩大范围重检；若仍不足则分析已有论文并告知用户 |
| 检索结果过多 | 增加过滤条件，取 Top-15 供用户选择 |
| 论文无法通过 arxiv 下载 | 说明原因，提供链接建议用户手动获取 |
| 论文正文超长（50页+） | 优先分析方法与实验章节，概括相关工作与附录；报告开头标注"长篇论文，部分章节概括分析" |
| 仅能获取摘要 | 基于摘要生成初步分析并标注"[基于摘要分析]"，建议用户提供完整 PDF |
| 多篇论文同主题 | 逐篇生成独立分析报告，最后追加对比分析章节 |
| 用户未指定过滤条件 | 默认检索近 2 年论文（2024-2026），按相关性排序 |
| 知识库目录不存在 | 询问用户知识库路径，或辅助创建标准目录结构 |
| 链接或搜索失败 | 说明失败原因，请求用户提供 PDF、arXiv ID 或更准确的标题 |
| 非学术论文 | 说明其非论文性质并询问是否继续分析 |
| 仅掌握摘要或片段 | 标注"基于部分内容分析"，建议用户提供完整论文 |

## 9. 优化拓展策略

### 批量处理
1. 按主题相关性排序，优先处理最相关的论文
2. 每篇论文独立走完下载→分析→整理流程
3. 所有论文完成后再生成汇总报告

### 论文质量标签
在筛选阶段为候选论文附加质量标签：
- **高影响力**：引用量高、来自顶会/顶刊
- **新工作**：近 1-2 年发表、方法新颖
- **有代码**：论文提供开源代码、可复现
- **综述类**：系统梳理领域进展

### 对比分析
多篇同主题论文时追加对比分析：
- 方法架构对比（可绘制 Mermaid 对比图）
- 性能数据对比表
- 创新点差异
- 适用场景建议

### 文献综述生成
用户选择"生成文献综述"时额外输出：
- 按时间线组织论文演进
- 归纳方法分类体系
- 指出研究空白与未来方向
- 输出为独立 MD 文件至 `论文/AI分析/`

### 引用关系探索
使用 `citation_graph` 探索论文引用关系：发现重要相关工作和后续论文，构建研究脉络。
